## 1. 一句话定位

把 Kovaak's 的练枪数据按**清单**分开追踪，并且让 "**今天该练的那份清单**" 成为一个开箱即用的界面 —— 打开就知道每条打什么、目标多少、离目标多远、打到第几条。

## 2. 用户与核心场景



| 项         | 内容                                               |
| --------- | ------------------------------------------------ |
| 用户        | 1 人（我自己），每天练枪 1h，目标**追 Viscose rank**（非实战上分）     |
| 每天的真实动作   | 打开当天清单（`Viscose基准-DayN-游玩清单.md`）→ 按条打 → 打完看结果    |
| 打开看板想立刻知道 | ① 今天每条的目标是多少 ② 我历史练得怎样 ③ 离目标 / 离升级线还差多少 ④ 打到第几条了 |
| 不想看到      | 别的清单的数据混进来；手工维护面板；每天改看板                          |

## 3. 三个核心概念



| 概念                | 含义                                                                     | 存在形式                                          |
| ----------------- | ---------------------------------------------------------------------- | --------------------------------------------- |
| **清单（List）**      | 一个 benchmark / 播放列表，如 `Voltaic Iron`(12 场景)、`Viscose S2 Easier`(39 场景) | 数据点上的 tag `list=<清单id>`                       |
| **每日清单（DayList）** | 当天要打的**子集 + 目标**，如 Day1「卡口双攻」7 条 / 33 轮                                | 独立表 `aim_daylist`（成员）+ `aim_daylist_meta`（概要） |
| **成绩数据**          | 每次练习的 score /accuracy/ 击杀间隔                                            | `aim_scenario` / `aim_kill`                   |

> **关键原则：成绩数据只带 "清单" 标签，不带 "每日清单" 标签。**
>
>  同一场景会在 Day1/Day3/Day7 反复出现，打上 daylist 标签会互相冲突；每日清单是一张 "视图定义" 表。

## 4. 数据模型



| 表                      | tags                                                     | fields                                    | 时间戳             | 用途                |
| ---------------------- | -------------------------------------------------------- | ----------------------------------------- | --------------- | ----------------- |
| `aim_scenario`         | scenario / session\_id / attempt\_no / source / **list** | score, accuracy, bpm                      | 练习时刻            | 成绩趋势              |
| `aim_kill`             | 同上（含 list）                                               | interval, offset                          | 每次击杀时刻          | 速率 / 节拍           |
| `aim_daylist`          | daylist / scenario / role                                | rounds, order, target\_score, target\_acc | **清单生效日 00:00** | 看板 D 的成员与目标线      |
| `aim_daylist_meta`     | daylist / label                                          | items, rounds\_total, run\_date           | 同上              | 清单排序、默认选中最新、清单日标记 |
| `aim_note` / `aim_log` | —                                                        | 文本 / 时长                                   | —               | 日志与感悟（已有）         |

## 6. 两个关键机制（决定能不能长期维护）

### 6.1 清单标签：一次配好，永久生效

导入时按场景名映射打上 `list` 标签；以后加 S2 Medium / Hard / Expert 只需在 `scenario_lists.json` 加一块 + 新建看板，**导入逻辑不用改**。

### 6.2 行重复：每天换清单，看板零改动



```
变量 day      = Day1 / Day2 / …（按日期倒序，默认自动取最新）

变量 scenario = 查询型：从 aim\_daylist 取 \$(day) 当天的场景名

行「今日清单」= 重复 for each \$scenario

&#x20;  ├─ 面板：\$scenario · 得分（历史 + 清单目标线 + 下一档线）

&#x20;  └─ 面板：\$scenario · 命中率（历史 + 清单门槛线 + 节拍占位）
```

Day1 → Day2 换清单时，**看板不改**，只有变量值变。

## 7. 更新流程（一次导全套）



```
curl.exe -X POST http://localhost:1881/import-aim     # Kovaak's：两个清单一起收

python aimlab\_import.py                               # Aim Lab

python tempo\_sync.py                                  # 节拍（Voltaic 4 场景；S2 占位）

python daylist\_sync.py                                # 每日清单落库（新增了 Day N 就跑）

curl.exe -X POST "http://localhost:1881/analyze-aim?date=YYYY-MM-DD"
```

配置与脚本（都在 `aim-tracker-docker/`）：



| 文件                    | 作用                                                             |
| --------------------- | -------------------------------------------------------------- |
| `scenario_lists.json` | **清单唯一事实来源**（场景、点击类、节拍、分组）                                     |
| `sync_lists.py`       | 把清单定义同步进 Node-RED `flows.json`（`--build` 重建，默认同步，`--check` 只查） |
| `daylist_sync.py`     | 解析 `Viscose基准-DayN-游玩清单.md` → `aim_daylist`（`--list` 只看不写）     |
| `tempo_sync.py`       | 节拍（S2 点击类先占位）                                                  |

## 9. 已知坑（实施时必看）



1. **改&#x20;**`flows.json`**&#x20;必须先停&#x20;**`aim-nodered`，否则改动被内存里的 flows 覆盖（容器停止时会回写文件）。

2. **每日清单的时间戳 = 清单生效日 00:00**，若清单是 "明天" 的，该点会落在 Grafana 默认时间范围（`to: now`）之外 → **看板 D 的默认时间范围要设&#x20;**`now-2d → now+1d`。

3. **重跑&#x20;**`daylist_sync.py`**&#x20;不能改时间戳**（必须用稳定的 "生效日零点"），否则同一份清单会产生重复点位。

4. InfluxDB 删除谓词**不支持&#x20;**`OR`，要按 measurement 分开删；`aim_daylist` 数据可由 md 随时重建。

5. Flux `pivot(rowKey:["_time"])` 在同时间多序列时会报错 → 核验用 `filter + keep`，别用 pivot。

6. 白名单外的 CSV **不写去重表**，所以扩白名单后能自动补收历史文件（本次 39 条就是这样补进来的）。

7. Grafana provisioning 改动需 `docker restart aim-grafana` 才生效；改动前先备份 JSON。

## 11. 数据怎么进页面 / 每天一个页面怎么实现 / 能不能导入计划自动生成

### 11.1 数据是怎么进到页面里的（链路）



```
Kovaak's 打完一局

&#x20; └─ 游戏自动写 stats/<场景> - Challenge - 时间 Stats.csv

&#x20;       └─ Node-RED「解析 stats 并场次分组」：按白名单(51 场景)取文件

&#x20;            ├─ 写 InfluxDB \`aim\_scenario\` → score / accuracy  （每条 = 一次练习）

&#x20;            └─ 写 InfluxDB \`aim\_kill\`     → interval / offset （每次击杀的间隔与偏移）

Grafana 面板 ── Flux 查询（filter scenario + \_field）──> 实时画线

每日清单（Day N）

Viscose基准-DayN-游玩清单.md（我的计划表格）

&#x20; └─ python daylist\_sync.py

&#x20;       ├─ 写 \`aim\_daylist\`      → 成员（哪个场景、几轮、角色、目标分、命中率门槛）

&#x20;       └─ 写 \`aim\_daylist\_meta\` → 概览（清单日、总轮数、条数）

Grafana 看板 D 用变量读成员，用面板重复自动生成每一项；目标线直接读 target\_\* 字段
```

**要点**：看板不存数据，只存 "查询与样式"；数据一律在 InfluxDB 里，页面每次打开实时查。所以更新数据 = 跑导入脚本，不需要碰看板。

### 11.2 看板 D 怎么做到 "每天一个页面"

**不是**每天生成一个看板文件（那样会越堆越多，还得手工排面板）。真实做法是**一个看板 + 两级变量 + 行重复**：



| 变量 / 机制               | 说明                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------- |
| 变量 `day`（下拉）          | 值取自 `aim_daylist_meta`，**按清单日倒序 → 默认选中最新一天**（这就是 "自动匹配今天"）；想看昨天，下拉切一下              |
| 变量 `scenario`（查询型、隐藏） | 取 `$day` 那份清单的全部场景名                                                                |
| 行「今日清单」重复             | 设置 **Repeat for each value of&#x20;**`scenario`，行里放两块面板（得分、命中率），查询用 `$scenario` 过滤 |

→ 结果：Day1→Day2→DayN 换清单时**看板一行都不用改**，只有变量值变了。

→ 每天 "看起来是一个新页面"，实质是同一个看板的变量切换。

### 11.3 能不能 "导入计划就自动生成"

能，而且已经跑通（Day1 就是这么进去的）：



1. **放文件**：把当日清单写成 `Viscose基准-DayN-游玩清单.md`（表格格式，含场景名 / 轮数 / 角色 / 目标分 / 命中率门槛）→ 放到项目根目录

2. **一条命令**：`python daylist_sync.py` → 解析入库（幂等，重跑不会重复）

3. **看板自动出现**：打开看板 D 时 `day` 变量已是它（默认取最新），无需任何看板操作

进一步自动化（按需选）：



* **并进 "更新" 流程**：每次说 "更新" 我一起跑 `daylist_sync.py`（已写进流程）

* **一个 bat 一次跑全套**：`import-aim` + `aimlab_import` + `tempo_sync` + `daylist_sync`（可放桌面）

* **定时任务**：用 WorkBuddy 自动化每天固定时间自动同步（例如每天 09:00）

* Kovaak's 的 `*.playlist.json` 也能当输入源（`daylist_sync.py` 已支持从它兜底取场景名与轮数）

### 11.4 节拍怎么进页面（占位说明）

节拍是人工值，面板位置与数据字段（`scenario_lists.json` 的 `tempo`）已留好、**值空着**。你哪天说 "CatClick 稳 60"，写进配置 → `tempo_sync.py` 落到 `aim_scenario.bpm` → 面板自动出线，不用改看板。
