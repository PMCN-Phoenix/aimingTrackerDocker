## 〇、v2 新增：「每日清单（Day N）」动态视图

**你的思路**：每天练的不是固定清单，而是当天的 Day N 清单（如 `Viscose基准-Day1-游玩清单.md`，7 条 / 33 轮）。希望系统**读懂今天这份清单里的确定项目**，把它们的**历史**显示出来。

### 已确认的事实（Day1 文件实测）

- `Viscose基准-Day1-游玩清单.md` 里有一张规整表格，**可机器解析**：

  | # | 场景 | 轮数 | 这一段要干什么 | 完成 |
  | --- | --- | --- | --- | --- |
  | 3 | `PGTI Voltaic Easy Smoother` | ×3 | **卡口 A**：目标 **700**（现在 696，只差 4 分） | ☐ |
  | 5 | `Pasu Voltaic Reload Easier` | ×7 | **主项**：37 → **46**，命中率 **≥75%** | ☐ |

  → 能解析出：**场景名 / 轮数 / 角色（热身·卡口·主项·疲劳巩固）/ 目标分 / 命中率门槛**
- 同时存在 `Viscose基准-Day1游玩清单.playlist.json`（Kovaak's 格式，只有 `scenario_name` + `play_Count`）→ 可作**兜底数据源**（场景名与轮数），目标值只在 md 里。

### 设计：每日清单落库为「清单成员表」

新建 measurement **`aim_daylist`**（**不往数据点打标签**，见下方"关键原则"）：

| 维度 | 值 |
| --- | --- |
| tags | `daylist`（如 `Day1`）、`scenario`、`role`（热身/卡口/主项/巩固） |
| fields | `rounds`（要求轮数）、`order`（第几条）、`target_score`、`target_acc` |
| 写入 | 新增脚本 `daylist_sync.py`：扫描 `Viscose基准-Day*-游玩清单.md` → 解析表格 → 幂等 upsert |

**关键原则：不给你练出来的数据打 `daylist` 标签。**
理由：同一个场景会在 Day1 / Day2 / Day5 反复出现，如果数据点带 daylist 标签就会互相冲突；`aim_daylist` 是**"视图定义"（哪些场景属于哪天的清单）**，与**"测量数据"（场景成绩）**分离 —— 这也是"清单"与"每日清单"两层概念的分界。

### 设计：看板「今日清单 · Viscose」

| 区域 | 内容 |
| --- | --- |
| 顶部 | 变量 `daylist`（Day1 / Day2 / …，来源 `schema.tagValues(tag:"daylist")`），可手选回看历史某天的清单；默认**自动取当天**（按文件名里的日期，如 `（9/17）`），匹配不到则取最新 |
| 完成度行 | 每条：**要求轮数 vs 今天实际打了多少轮**（从当天 stats 自动数），一眼看出"打到第几条、还剩几条" |
| 主体 | 清单里的每个场景一行两栏（照搬看板 A 的双栏） |
| 得分面板 | 历史得分折线 + **目标分虚线**（清单指定，如 PGTI 700） + **下一档线虚线**（榜单） |
| 命中率面板 | 历史命中率折线 + **门槛线**（清单指定，如 75%） |

**这与看板 B（S2 全量 39 场景）的区别**：B 是"整个清单的资产盘点"，本看板是"**今天这一份任务**的历史参照"——每天打开就知道该打什么、目标多少、离目标多远。

## 一、设计原则（三条）

1. **一个清单 = 一个看板**，同级、同结构、可互跳；不把 S2 塞进现有看板的分区里。
2. **清单是数据层概念，不是看板层概念**：导入时给每条数据打上「属于哪个清单」的标识，以后加 S2 Medium / Hard / Expert 只是新增一个清单值 + 新建一个看板，不用再改导入逻辑。
3. **现有看板 URL 不变、历史数据零迁移**（`aim-scenarios-v2` 继续用；12 场景的旧数据缺新标识，但看板按场景名过滤，不受影响）。

## 五、看板 B（新建）「练枪训练 · Viscose S2 Easier」

- uid：`viscose-s2-easier` ｜ URL：`http://localhost:3001/d/viscose-s2-easier` ｜ 同一个 Grafana folder「练枪」
- 因为 S2 是**追 rank** 的清单，主视图不做成"39 行折线墙"，而是"**先看进度、再看趋势**"：

| 区域 | 面板 | 内容 |
| --- | --- | --- |
| **Row 0 · 进度总览** | 4 个 stat + 1 个 bargauge | ① 已上榜 32/39 ② 当前最低档位 ③ 平均离下一档进度 % ④ 今日已练 N/39 ⑤ **39 场景「当前分 ÷ 下一档线」横向进度图**（≥100% 变绿 = 已达下一档） |
| **Row 1 · rank 进度总表** | 1 个 table（39 行） | 场景 ｜ 分组 ｜ 当前分 ｜ 档位 ｜ 下一档线 ｜ 差距 % ｜ 最近命中率 ｜ 最近成绩时间 |
| **Row 2 · 主项：动态跟枪/控枪** | 19 个面板（**默认展开**） | 每场景 1 面板：得分折线 + **下一档线虚线** + 命中率（右轴） |
| **Row 3 · 动态点击** | 2 个面板 | VT Bounceshot / Popcorn MV（同结构，含下一档虚线） |
| **Row 4 · 静态点击/切换** | 18 个面板（**默认折叠**） | 同上结构，平时不展开，避免干扰 |

- 面板 id 规划：`600-604` 总览 ｜ `610` 进度总表 ｜ `620-658` 场景面板（39 个）｜ `900+` 预留（节拍 / 速率）
- 与 A 同理加 **dashboard link** 跳回

**为什么把"下一档线"画进每个场景面板**：追 rank 时你需要的不是"这条线涨没涨"，而是"离那条线还有多远"——这是这个看板与 A 看板的核心差别。

## 十一、MVP（v0.1）产品设计 —— 从最小可用闭环开始

### 11.1 MVP 只回答一个问题

> **"今晚练 Day N，我打开电脑就知道每条该打什么、目标多少、我离目标还差多远、打到第几条了。"**

这一句成立，MVP 就成立。其它（全量清单资产盘点、Aim Lab 迁出、报告改造）全部往后放。

### 11.2 MVP 范围（做 / 不做）

| # | 做 | 说明 |
| --- | --- | --- |
| 1 | **数据地基** | 白名单扩到 51（12 Voltaic + 39 S2）、新点打 `list` tag、击杀解析全开（39 场景） |
| 2 | **补收历史** | 把 09-16 那 39 条 S2 数据收进来（否则看板是空的） |
| 3 | **每日清单落库** | `daylist_sync.py` 解析 `Viscose基准-Day1-游玩清单.md` → `aim_daylist`（成员 / 轮数 / 目标分 / 门槛 / 角色） |
| 4 | **看板 D（今日清单）** | 变量选清单 → 自动列出当天项目 → 每项「得分 + 命中率」两块面板 + 清单目标线 + 下一档线 |
| 5 | **完成度总览** | 每条任务的「要求轮数 vs 当天已打轮数」 |

### 11.3 MVP 的关键机制：面板**重复生成**

每天清单都在变（Day1 是 7 条，Day2 可能 9 条），**靠手工排面板就等于每天改看板**。所以用 Grafana 原生的**行重复（Repeat by variable）**解决：

```
变量 day      = Day1 / Day2 / …（按日期倒序 → 默认自动取最新 = 你要的"自动为主"）
变量 scenario = 【查询型】从 aim_daylist 取 $("#day") 当天清单的全部场景名
                        ↑ 清单变了这个变量自动跟着变，看板不用动

行「今日清单」= 重复 for each $scenario
   ├─ 面板：$scenario · 得分（历史折线 + 清单目标分虚线 + 下一档线虚线）
   └─ 面板：$scenario · 命中率（历史折线 + 清单门槛虚线 + 节拍占位位）
```

**收益**：Day1 → Day2 → DayN 换清单时，**看板零改动**，只有变量值变。这是"每天不同清单"能长期维护的地基。

### 11.4 MVP 验收标准

- [ ] 打开看板 D，默认就是**当天**那份清单（不用手选）
- [ ] 清单里每条任务都能看到**历史得分/命中率曲线** + **目标线与门槛线**
- [ ] 完成度表能看出"打到第几条"，打完的显示达标
- [ ] 换 Day2 清单后（我生成 Day2 文件），看板**不改动**也能显示新清单
