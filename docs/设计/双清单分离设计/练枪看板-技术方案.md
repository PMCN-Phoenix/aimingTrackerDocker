# 练枪看板 · 技术方案

> 版本 v1 ｜ 2026-09-17 ｜ 对应需求：`练枪看板-产品设计文档.md`
> 选型结论：**Grafana + 自绘面板插件（S2）** ｜ 导入层保持 Node-RED ｜ 数据层 InfluxDB 不变
> 本文是实现级方案（怎么做），设计意图见产品设计文档，选型对比见技术栈选型文档。

---

## 1. 目标与范围

**目标**：四看板（A Voltaic / B Viscose S2 / C Aim Lab / D 今日清单）在同一 Grafana 内，清单分离、每日清单开箱可用。

**范围内**：数据层改造、导入层白名单与清单标签、展示层面板与变量、部署方式与验收。
**范围外（v0.5 后再议）**：把导入解析从 Node-RED 迁到 Python、历史 `list` tag 回填、节拍真值填充、Medium/Hard/Expert 档位。

---

## 2. 总体架构

```
               ┌─────────────── 数据产生 ───────────────┐
Kovaak's  ──▶ stats/*.csv                      Viscose基准-DayN-游玩清单.md
（游戏）        │                                        │
               ▼                                        ▼
        Node-RED「解析 stats」                    Python daylist_sync.py
        （白名单 51 场景 / 每次击杀）               （解析清单表格）
               │                                        │
               ▼                                        ▼
        ┌─────────────────── InfluxDB 2.7（bucket=aim）────────────────┐
        │ aim_scenario(score,accuracy,bpm)   aim_kill(interval,offset)  │
        │ aim_daylist(rounds,order,target_score,target_acc)             │
        │ aim_daylist_meta(items,rounds_total,run_date)                 │
        │ aimlab_task(score,accuracy)   aim_note / aim_log              │
        └───────────────────────────┬───────────────────────────────────┘
                                    ▼  Flux 查询
        ┌──────────────────── Grafana 10.4（:3001）────────────────────┐
        │ A aim-scenarios-v2     12 场景趋势 + 速率 + 节拍              │
        │ B viscose-s2-easier    格子填色总表（自绘 HTML 面板）         │
        │ C aimlab               3 任务趋势                            │
        │ D 今日清单             day 变量 + 行重复 + 图表 + 对比卡      │
        └──────────────────────────────────────────────────────────────┘
```

**职责边界**：看板只存"查询 + 样式"；成绩数据只带**清单标签**（`list`），每日清单是**独立视图表**，两者不混。

## 3. 技术选型（结论与依据）

| 层 | 选型 | 依据 |
| --- | --- | --- |
| 时序库 | **InfluxDB 2.7**（沿用） | 已有数据与 Flux 查询资产；数据量小、写入靠脚本，无需替换 |
| 可视化 | **Grafana 10.4.0**（沿用） | 变量 / 时间范围 / 自动刷新 / provisioning 全部现成；四看板同级互跳 |
| 自绘表格 | **gapit-htmlgraphics-panel 2.2.3** | 原生 Table 无法表达"跨列比较"的格子填色；该插件可在面板内写 HTML+CSS+JS，1:1 还原 Demo |
| 备用面板 | marcusolsson-dynamictext-panel 6.3.0（Business Text）、grafana-polystat-panel 2.1.16 | 已装好备着；模板驱动或热力格近似 |
| 导入解析 | **Node-RED 3.1**（保持） | 现有链路稳定；迁移到 Python 列入 v0.5，避免一次改两头 |
| 辅助脚本 | **Python 3.13**（7 个脚本） | 清单同步、每日清单、节拍、感悟表、Aim Lab 导入 |
| 容器 | Docker Desktop + docker compose | 与健身/无畏契约两套并存（端口 3001/1881/8087） |

**关键实测结论（2026-09-17）**
| 项 | 结果 |
| --- | --- |
| 容器外网 / grafana-cli | ✅ 可用（可装插件） |
| `volkovlabs-dynamictext-panel` | ❌ 404（slug 已下架） |
| `gapit-htmlgraphics-panel` | ✅ v2.2.3 已加载 |
| `marcusolsson-dynamictext-panel` | ✅ v6.3.0 已加载（显示名 Business Text） |
| `grafana-polystat-panel` | ✅ v2.1.16 已加载 |

> ⚠️ **不要用 `GF_INSTALL_PLUGINS` 环境变量固化插件**：实测容器启动时会重新联网下载并报 `404: Plugin not found`，导致启动失败 → 重启循环。
> 正确做法：插件装在挂载卷 `./grafana_data/plugins`（重启/重建都保留）；数据卷若被清空，手动重装见 §8.3。

## 4. 数据层设计

### 4.1 表结构

| 表 | tags | fields | 时间戳语义 |
| --- | --- | --- | --- |
| `aim_scenario` | scenario / session_id / attempt_no / source / **list** | score, accuracy, bpm | 练习时刻（北京时间换算前的 UTC） |
| `aim_kill` | 同 `aim_scenario` | interval（与上次击杀间隔 s）、offset（距开场 s） | 每次击杀时刻 |
| `aim_daylist` | daylist / scenario / role | rounds, order, target_score, target_acc | **清单生效日 00:00（本地）** |
| `aim_daylist_meta` | daylist / label | items, rounds_total, run_date(字符串) | 同上 |
| `aimlab_task` | task / taskId / source=aimlab | score, accuracy | 练习开始时刻 |

### 4.2 关键约定

1. **`list` 标签**：`voltaic-iron` / `viscose-s2-easier`；由导入时按场景名映射写入，未来加档位只新增值。
2. **每日清单不打在成绩数据上**：同一场景跨天重复出现，打标签会互相冲突 → 用成员表做"视图定义"。
3. **每日清单时间戳必须稳定**（= 生效日零点），**不能用 `now()`**，否则重跑产生重复点位。若清单日是"明天"，该点会落在 Grafana 默认 `to: now` 之外 → **看板 D 默认时间范围设 `now-2d → now+1d`**。
4. **幂等**：`aim_scenario`/`aim_kill` 按文件名去重；`aim_daylist*` 靠"稳定时间戳 + 相同 tags"覆盖写。

## 6. 展示层设计

### 6.1 面板与 ID 规划

| 看板 | uid | 面板构成 | 面板 ID 段 |
| --- | --- | --- | --- |
| A（已有） | `aim-scenarios-v2` | 12 场景 ×2 + 速率 6 + 节拍 4 + Aim Lab 6 = 40 | 100–123 / 300–305 / 400–405 / 500–503 |
| B（新建） | `viscose-s2-easier` | 顶部 4 统计卡 + 档位分布（原生 barchart）+ **格子填色总表（HTML graphics 自绘）** | 600–604（卡）、610（表） |
| C（新建） | `aimlab` | 3 任务 ×（得分 + 命中率） | 700–705 |
| D（新建） | `viscose-daylist` | 完成度表（table）+ 重复行（每场景：得分/命中率 timeseries + 对比卡 HTML graphics） | 800（完成度）、810+（重复行面板） |

四个看板放在同一 Grafana folder「练枪」，用 dashboard links 互跳。

### 6.2 变量与重复机制（看板 D）

| 名称 | 类型 | 定义 |
| --- | --- | --- |
| `day` | Query（InfluxDB，Flux） | 取 `aim_daylist_meta` 的 daylist，**按 `_time` 倒序** → 默认选中最新一天（即"自动匹配今天"） |
| `scenario` | Query（InfluxDB，Flux，隐藏） | 取 `aim_daylist` 中 `daylist == $day` 的全部场景名（Flux 用 `v.day`） |

行「今日清单」设置 **Repeat for each value of `$scenario`**，行内面板查询用 `r.scenario == "$scenario"` 过滤；对比卡的目标值来自 `aim_daylist` 的 `target_score` / `target_acc`（同一查询帧内取 `order == 当前`）。

### 6.3 自绘面板（HTML graphics）数据契约

面板内的 JS 通过 `htmlNode.context` 拿到已查询的数据帧（`context.panel.data.series[i].fields / .values`）。

**B 表所需数据（一次查询产出）**：每个场景一行，字段 ——
`scenario`（字符串）、`score`（当前分，取最新一次）、`pct`（到下一档进度%）、`targets[9]`（9 档线）、`achIdx`（已达档数）、`cat` / `sub`（大类 / 子类）、`subRank` / `subPct`（子类档位与进度）。

**实现方式**：由于 Flux 输出的是"长表"（每场景 9 行 target），面板 JS 里先做 pivot（按 scenario 聚合），再渲染 HTML 表格：
- 每个档位格：`achIdx` 与列序比较 → `ach`（绿 #C0DD97）/ `cur`（蓝 #B5D4F4）/ `fut`（灰 #F1EFE8）
- 进度条：`score / targets[achIdx]`，≥95% 绿、85–95% 橙
- 大类行 / 子类行：按 cat、sub 插入分组行（子类行显示 `subRank` + `subPct`）
- 样式直接复用 Demo（`练枪看板-Demo.html`）里的 CSS

**D 对比卡所需数据**：`scenario`、`target_score`、`target_acc`、`next_line`、`score`、`accuracy` → 渲染 3 行对比 + 进度条。

> 备选实现：若 HTML graphics 的面板内 JS 受限，可改用 Business Text（Handlebars + 辅助 JS），或在面板里改用一个 Flux 查询把数据预整形为"宽表"（每档一列）以简化前端。

## 7. 关键技术细节与坑（实施必看）

| # | 坑 | 对策 |
| --- | --- | --- |
| 1 | 改 `flows.json` 被内存覆盖 | 先 `docker stop aim-nodered`，改完再 `start`；改动前自动备份 |
| 2 | `GF_INSTALL_PLUGINS` 导致重启循环（本次踩到） | 不用它；插件放数据卷，清空后手动重装 |
| 3 | Flux 时间字面量带时区偏移（`2026-09-13T00:00:00+08:00`）静默返回空 | 用相对时间或 `time(v:"...")` |
| 4 | InfluxDB 删除谓词**不支持 OR** | 按 measurement 分次删 |
| 5 | Flux `pivot(rowKey:["_time"])` 同时间多序列报错 | 核验用 `filter + keep` |
| 6 | annotated CSV **多套表头**（新点带 `list`、旧点没有） | 解析器按表头分段；`keep()` 必须包含 `_time` |
| 7 | 每日清单点落在未来 → 看板看不见 | 看板 D 默认时间范围 `now-2d → now+1d` |
| 8 | 中文场景名在 curl 传 Flux 时编码错 | 用 Python/`/api/ds/query` 验证，别用 curl 直传中文 |
| 9 | Grafana provisioning 改动不生效 | 改完 `docker restart aim-grafana` |
| 10 | 本地 `localhost` 解析异常（本机 hosts 未绑） | 一律用 `127.0.0.1` |

## 8. 部署与运行

### 8.1 容器

| 容器 | 端口 | 说明 |
| --- | --- | --- |
| `aim-influxdb` | 8087 | org=`aim-org`，bucket=`aim` |
| `aim-grafana` | 3001 | admin/admin；provisioning 目录挂载 |
| `aim-nodered` | 1881 | stats 目录只读挂载 `/stats` |

### 8.2 日常更新（一条链路）

```powershell
curl.exe -X POST http://127.0.0.1:1881/import-aim      # Kovaak's（两清单一起收）
python aimlab_import.py                                # Aim Lab
python tempo_sync.py                                   # 节拍
python daylist_sync.py                                 # 每日清单（新增 Day N 时必跑）
curl.exe -X POST "http://127.0.0.1:1881/analyze-aim?date=YYYY-MM-DD"
```

### 8.3 插件重装（数据卷被清空时）

```powershell
docker exec aim-grafana grafana-cli plugins install gapit-htmlgraphics-panel
docker exec aim-grafana grafana-cli plugins install marcusolsson-dynamictext-panel
docker restart aim-grafana
```

### 8.4 备份要点

`grafana_data/`（含看板与插件）、`influxdb_data/`、`nodered_data/flows.json`、`scenario_lists.json`、`tempo_config.json`、`Viscose基准-Day*-游玩清单.md`、`reports/`。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 自绘面板插件（第三方）升级/不兼容 | B/D 面板失效 | 版本随数据卷固定；面板配置随 dashboard JSON provisioning 可回滚；降级方案 = 原生 Table + 状态列（✓/→/·） |
| 面板内 JS 维护成本 | 改样式要动面板代码 | 模板化：一份渲染函数 + 数据驱动；Demo 作为样式参照 |
| Node-RED flows 改动风险 | 导入中断 | 改前停容器 + 自动备份 + 导入后核对计数 |
| 磁盘/数据卷丢失 | 看板与插件丢失 | §8.4 备份要点；插件重装命令已备 |
| 每日清单格式漂移（md 表格） | 解析失败 | 解析器对"目标分/门槛"用宽松正则；失败时 `--list` 先空跑核对 |
