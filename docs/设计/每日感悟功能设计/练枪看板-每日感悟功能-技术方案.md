## 1. 技术栈选型（已确认）



| 层    | 选型                                         | 理由                                                             |
| ---- | ------------------------------------------ | -------------------------------------------------------------- |
| 数据存储 | InfluxDB 2.7（measurement `aim_reflection`） | 与 aim\_scenario/aim\_daylist 统一，Grafana 原生查询，Flux 按时间范围取最近 3 天 |
| 前端弹窗 | gapit-htmlgraphics-panel 自绘 modal          | 800 面板已是 gapit 自绘表格，场景名加 click + modal 最自然，不跳转不打断上下文           |
| 写入方式 | Python 脚本 `reflection_write.py`，对话式写入      | 与现有 8 个 Python 脚本一致，简单可靠，同 scenario+date 覆盖写入可控                |
| 查询方式 | 预加载最近 7 天到 JS 变量                           | 感悟数据量小，预加载一次，点击无延迟                                             |
| 编辑模式 | 第一版只读展示，编辑走对话 + 脚本                         | 降低复杂度，未来如需弹窗内编辑再加 Node-RED API                                 |

## 2. 数据模型详细设计

### 2.1 measurement：`aim_reflection`



| 元素             | 类型     | 值                     | 说明                                    |
| -------------- | ------ | --------------------- | ------------------------------------- |
| `_measurement` | —      | `aim_reflection`      | 固定                                    |
| `scenario`     | tag    | 场景名                   | 与 aim\_scenario.scenario 完全一致（大小写、空格） |
| `daylist`      | tag    | `Day1` / `Day2` / ... | 可选，标识所属清单日                            |
| `_field`       | —      | `note`                | 固定，感悟文本                               |
| `_value`       | string | 感悟内容                  | 文本，支持多行（InfluxDB string field 可存换行）   |
| `_time`        | time   | 当天 00:00:00 +08:00    | 感悟对应的日期，非写入时刻                         |

### 2.2 唯一性与覆盖写入



* **唯一键**：scenario + daylist + \_time（当天 00:00）

* **覆盖写入**：InfluxDB 同 tag+field+time 写入会自动覆盖旧值，无需先删后写

* **时间戳计算**：`int(datetime.datetime(today.year, today.month, today.day, tzinfo=TZ_CN).timestamp())`

### 2.3 写入示例（Line Protocol）



```
aim\_reflection,scenario=1w2ts\ reload\ smallflicks\ larger,daylist=Day1 note="今天手感不错，跟枪稳" 1726598400
```

## 3. 写入脚本设计：`reflection_write.py`

### 3.1 命令行接口



```
python reflection\_write.py --scenario "场景名" --note "感悟内容" \[--date 2026-09-18] \[--daylist Day1]
```



| 参数           | 必填 | 默认值                        | 说明                         |
| ------------ | -- | -------------------------- | -------------------------- |
| `--scenario` | ✅  | —                          | 场景名，必须与 aim\_scenario 完全一致 |
| `--note`     | ✅  | —                          | 感悟文本内容，支持多行（用引号包裹）         |
| `--date`     | ❌  | 当天（Asia/Shanghai）          | 感悟对应的日期，格式 YYYY-MM-DD      |
| `--daylist`  | ❌  | 自动从 daylist\_dates.json 推断 | 所属清单日                      |

### 3.2 脚本逻辑



```
1\. 解析参数

2\. date → 当天 00:00 +08:00 的 Unix 时间戳

3\. daylist 推断：读 daylist\_dates.json，找到 date 对应的 daylist

4\. 构造 Line Protocol（注意 scenario 中的空格需转义为 \`\ \`）

5\. POST 到 InfluxDB Write API（/api/v2/write?org=aim-org\&bucket=aim\&precision=s）

6\. 输出写入结果（scenario / date / daylist / note 摘要）
```

### 3.3 场景名校验（可选）

写入前可选校验 scenario 是否存在于 aim\_scenario 中，防止拼写错误。查询：



```
from(bucket: "aim") |> range(start: -30d)

&#x20; |> filter(fn: (r) => r.\_measurement == "aim\_scenario" and r.scenario == "<场景名>")

&#x20; |> keep(columns: \["scenario"]) |> limit(n: 1)
```

若返回空，输出警告但仍允许写入（因为可能是新场景首次有感悟）。

## 4. 800 面板查询设计

### 4.1 新增 target：refId `C`（aim\_reflection 查询）



```
from(bucket: "aim")

&#x20; |> range(start: -7d, stop: 2d)

&#x20; |> filter(fn: (r) => r.\_measurement == "aim\_reflection" and r.\_field == "note")

&#x20; |> keep(columns: \["\_time", "\_value", "scenario", "daylist"])
```



* **范围**：`-7d` 到 `+2d`（覆盖当天 + 最近 3 天历史 + 容错）

* **返回**：每条感悟一行，含 \_time（日期）、\_value（感悟文本）、scenario、daylist

### 4.2 现有 target 复用



| refId | 查询                                    | 用途     | 新增用途                   |
| ----- | ------------------------------------- | ------ | ---------------------- |
| A     | `day_json_flux`（aim\_daylist rowJson） | 渲染完成度表 | 弹窗中提取目标分 / 门槛 / 角色     |
| B     | `count_flux`（aim\_scenario 当日 count）  | 已打轮数   | 弹窗中提取当天得分 / 命中率（需扩展查询） |
| C     | **新增** aim\_reflection                | —      | 弹窗中提取当天感悟 + 最近 3 天历史   |

### 4.3 count\_flux 扩展（refId B）

现有 count\_flux 只查当日轮数（count）。弹窗需要当天得分 / 命中率，有两种方案：

**方案 A（推荐）**：不改 count\_flux，新增 refId D 查询当天得分 / 命中率



```
from(bucket: "aim")

&#x20; |> range(start: \_cs, stop: \_ce)

&#x20; |> filter(fn: (r) => r.\_measurement == "aim\_scenario" and (r.\_field == "score" or r.\_field == "accuracy") and r.list == "viscose-s2-easier")

&#x20; |> group(columns: \["scenario", "\_field"])

&#x20; |> max()
```

（\_cs/\_ce 与 count\_flux 相同，基于 rundate 变量计算当天范围）

**方案 B**：在 count\_flux 中同时查 count 和 max，但 Flux 单查询难以同时返回两种聚合

**选择方案 A**，新增 refId D，职责清晰。

## 9. 风险与边界



| 风险                        | 影响           | 缓解措施                                      |
| ------------------------- | ------------ | ----------------------------------------- |
| gapit panel JS 沙箱限制       | window 变量不可用 | 改用闭包变量或 htmlNode 自定义属性                    |
| 场景名不匹配（大小写 / 空格）          | 感悟查不到        | 写入时校验 scenario 存在于 aim\_scenario；点击时用精确匹配 |
| InfluxDB string field 换行符 | 感悟多行显示异常     | CSS 加 `white-space: pre-wrap`             |
| 同一天同场景覆盖写入                | 旧感悟被覆盖       | 设计上就是覆盖写入，符合 "每天一条" 的语义                   |
| provisioning 重载延迟         | 修改后看板不立即更新   | 等 30 秒，或手动刷新 Grafana                      |
| 800 面板查询数增加（3→5）          | 面板加载稍慢       | 感悟数据量小，影响可忽略                              |
| 热身项无目标分 / 门槛              | 弹窗显示空        | 显示 "—" 占位                                 |
| aim\_bench\_row 无该场景数据    | 下一档线为空       | 显示 "—" 占位                                 |
