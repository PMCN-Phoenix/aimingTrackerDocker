## 一、结论先行

### 1.1 这个场景是什么

官方描述（作者原文，Steam 创意工坊 **id 1620729015**，原版）：

> "**Smoothly track very thin bots that make fast strafes.**"

你打的这个变体（**id 3584328702**，2025-10-10）：

> "Theo asked me to make this. Smooth Thin Strafes w/ **jumps** and **slightly more responsive physics** than the original."

也就是说：**极细的目标 + 快速的变向**，Raspberry 版还额外加了「跳跃」和「更灵敏的物理（变向更干脆）」。

### 1.2 你的眼睛为什么"必然"反应不过来

不是你的眼睛差。是**这个目标在生理上就追不了**。

| 事实 | 数值 | 后果 |
|---|---|---|
| 目标每秒变向 | **1.8–3.1 次** | 单向运动只持续 **0.2–0.6 s** |
| 眼球平滑追踪的启动潜伏期 | **约 0.1 s**（眼动生理常规值） | 每次变向，你光"启动"就用掉单程时间的 **1/3–1/2** |
| 平滑追踪对往复目标的增益 | 1 Hz 以上急剧下降 | 0.2–0.6 s 单程 = **0.8–2.5 Hz**，正好在崩塌区 |
| 跳视（saccade）潜伏期 | 约 0.2 s | 追不上就补跳视，**每次补都要多花 0.2 s** |
| 跳视期间的视觉 | 对比敏感度显著下降（**跳视抑制**） | "补"的那一下你**看不见** |

**结论：眼球在这个场景里不是"反应慢"，是"根本没有能跟上的运动系统"。**

### 1.3 关键发现：WR 玩家的相机速度 ≈ 0

这是本次调研最重要的一条，也是**反直觉**的。

我把 WR 录像切成两段（40–52 s / 62–72 s），同时测了两个量：

| 量 | 窗口 A | 窗口 B |
|---|---|---|
| **目标**屏幕速度（中位） | 47 px/s（5.0°/s） | 62 px/s（6.7°/s） |
| **相机**速度（背景光流，中位） | **0.0 px/s** | **0.0 px/s** |
| 目标 x 均值 | **480**（= 屏幕正中） | **479** |
| 准星-目标偏差 \|e\| 中位 | **3.1 px（0.34°）** | **3.6 px（0.39°）** |
| \|e\| < 6 px 的时间占比 | **69%** | **64%** |

最后一行是关键交叉验证：**\|e\| < 6 px 占 69%，而结算命中率是 70.65%。** 两个独立来源对上了 → 测量链可信。

而"相机速度 = 0"意味着：

> **WR 玩家没有在跟这个目标。他把准星停在目标来回摆动的中心（屏幕正中），然后手基本不动，让目标自己扫过来。**

目标 x 的均值精确等于 480（屏幕正中），这不是巧合——这是**刻意把准星放在摆动弧的中点**的结果。

### 1.4 主结论

> **"眼睛反应不过来"的解法不是练眼睛，是别让眼睛去追。**

你现在做的是：眼睛跟着目标跑 → 目标每 0.3 秒反向 → 你的眼睛每次都要重新启动 → 永远落后半拍 → 你感觉"眼睛反应不过来"。

正确做法是：**眼睛锁死在屏幕中心的一小块区域，让目标自己扫进这一块。** 你不需要追踪它，你只需要在它扫进来的那一下**不动**。

B站 173 万播放的《中文互联网最好的瞄准教学》（`BV1zUjY6iEzs`）UP 主本人的回复，把这件事讲得比任何术语都清楚：

> "你把屏幕竖着 3 等分…在屏幕中心留下一小片区域，这个区域我们叫他 X。然后你只需要**保持你的眼球的视线投射在 X 里这片大区域**就可以了，你可以自由地看 X 区域里的任何东西。如果 A 和 C 有敌人，你就**把他拖入 X 来看，用手的移动代替你眼球的转动**。"

评论区一句 96 赞的补充更狠：

> "就是当从犄角旮旯拉出来人的时候，**转角色的眼睛而不转你自己的眼睛**。"

## 二、机制层：为什么"用眼睛追"在这个场景必然失败

### 2.1 眼球有两套系统，两套都不够快

| 系统 | 干什么 | 潜伏期 | 在本场景的表现 |
|---|---|---|---|
| **平滑追踪**（smooth pursuit） | 跟匀速运动的目标 | ~0.1 s | 目标 1.8–3.1 Hz 往复 → 增益崩塌，几乎跟不动 |
| **跳视**（saccade） | 把目标"跳"到中央凹 | ~0.2 s | 追不上就补跳视，但每补一次要 0.2 s，且**补的时候看不见** |

再加上第三条：**目标只有 1.3° 宽，完全落在中央凹里**——这恰恰是最坏的情况，见 2.3。

### 2.2 变向是平滑追踪的最差工况

平滑追踪是一个**速度闭环**：它根据视网膜上的滑移速度去匹配目标速度。它的两个特性决定了它做不了往复：

1. **有延迟**：你给的速度指令永远是 0.1 s 之前的。目标 0.3 s 反向，你的指令在 0.1 s 后才到位——**你永远在追一个已经反向的目标**。
2. **增益随频率下降**：目标做正弦/三角往复时，频率越高、追踪增益越低。0.8–2.5 Hz 已经在崩塌区，实际增益大约只有 0.3–0.5。**意思是：目标动 30°，你的眼睛只动 9–15°。**

所以变向瞬间，视网膜上的滑移速度**瞬间翻倍**（目标反向 = 相对速度 = 你的速度 + 目标速度）。这就是《跟枪学习完全攻略指南》里那句话的生理版本：

> "如果目标变向了，你往反方向修正，那么**目标相对于你速度是变得更快了**。"

### 2.3 细目标 → 逼你"对焦" → 触发跳视 → 跳视期间看不见

这条有直接的实验证据。**Heinen, Potapchuk & Watamaniuk (2016), J Neurophysiol 115:1220–1227**：

> "…'catch-up' saccades that are ubiquitous during pursuit **interrupt it and disrupt clear vision**."
>
> "Single-spot targets produced **lower pursuit acceleration** than larger objects."
>
> "…**catch-up saccade frequency was highest when it fit in the fovea**."
>
> "…the target **compels foveation**."

翻译成这个场景的话：

- 目标又细又小 → **完全落在中央凹内** → 大脑判定"这是个需要精确对焦的东西" → **强制启动跳视**；
- 跳视一旦启动，平滑追踪被打断，**视觉清晰度下降**（跳视抑制，对比敏感度在跳视前后显著降低）；
- 于是你看到的不是"目标在动"，而是"目标忽明忽暗、位置在跳"——**这就是"眼睛反应不过来"的主观体验**。

**注意这条最扎心的地方**：目标越细，跳视越多。所以这个场景的 "Thin" 不只是"难打中"，它是**专门为了破坏你的眼动而设计的**。

### 2.4 动态视力不是"练"出来的，是"用对策略"用出来的

**Palidis, Wyder-Hodge, Fooken & Spering (2017), PLoS One 12(2):e0172061** 研究了 23 名大学棒球队员的动态视力（DVA），结论是：

> "…distinct eye movement patterns — **minimizing eye position error, tracking smoothly, and inhibiting reverse saccades** — were related to dynamic visual acuity."

三个预测因子，逐条对应到本场景：

| 论文里的因子 | 在这个场景里是什么意思 |
|---|---|
| 最小化**眼位误差** | 眼睛别乱跑，锁在中心 |
| **平滑**追踪 | 不要用跳视去"抓" |
| **抑制反向跳视** | 变向时**不要**往回补那一下 |

第三条尤其重要：**"抑制反向跳视"= 变向瞬间不要用眼睛去追那一下。** 你越追，DVA 越差。

而 B站大东彦（`BV1Kq4y1E7oU`，55 万播放）给了一个更实操的说法，和论文完全对得上：

> "**瞄准的精髓是感知速度，而不是感知距离。**"
>
> "眼睛会参与瞄准的**开头和末尾**，但不会过多地参与瞄准定位的**中间过程**。"
>
> "**动态视力是贯穿整个用眼参与瞄准的全过程的**…我个人认为**没有什么能单独提高动态视力的方案**。"

最后一句很关键：**别去找"动态视力训练"。** 它不是一个可以单独练的肌肉，它是"眼动策略对不对"的结果。

### 2.5 一个被忽略的视觉锚点：粉色血条

实测：**血条宽 45–47 px（4.4°），比目标宽 3.2–3.3 倍，贴在目标上方 0.43°。**

这意味着两件事：

- **坏消息**：血条是画面里**对比度最高、面积最大**的移动物体（饱和粉在灰石墙上）。你的眼睛会本能地被它吸走——而判定区在它下方。
- **好消息**：血条是**比目标更好的速度读数器**。目标只有 1.3° 宽，横向几乎没有可读的边缘；血条 4.4° 宽，边缘清楚。**用血条读"它在往哪走、走多快"，用黑色本体确认"打没打中"。**

这一条和 Q004.10 的结论是同一个原理：**用大而清楚的物体读速度，用小而准的物体做判定。**

## 三、怎么打：五层，从最有效到最次要

### 第 1 层｜眼睛：锁中心，用余光（最高优先级）

这是唯一必须改的东西。

| 现在 | 改成 |
|---|---|
| 眼睛跟着目标左右跑 | **眼睛锁在屏幕中心约 1/3 屏宽的一小块区域**，不移动 |
| 用中央视觉"盯住"目标 | 用**周边视觉**感知"有东西在动 / 有东西扫进来了" |
| 目标跑到哪看到哪 | 目标扫进中心区时才需要"确认"，扫出去就交给余光 |

**判断标准**：如果你打完之后**眼睛酸、太阳穴紧**，说明你还在用眼睛追。正确状态下眼睛应该是"发散的、放松的"。

B站《一招制胜 高级FPS眼部追踪》（`BV17pMg6mEy8`，148 万播放）的训练口令就是这个：

> "请专注于看红色的准星，并**用余光追踪白色的小球**。**不要用力聚焦的去看，让眼睛保持放松。**"

### 第 2 层｜准星：停在摆动中心，不追

WR 玩家的实测：**相机速度 0 px/s，目标 x 均值 = 屏幕正中。**

具体做法：

1. 开局先看 3–5 秒，找到目标**左右摆动的中点**（不是它当前的位置，是它来回的中点）；
2. 把准星**停在这个中点上**；
3. 目标扫出去，**不动**；扫回来，**不动**；只有它连续两次往同一方向走（真的走了，不是往复）才跟。

这一条听起来"不作为"，但它是 WR 的实际做法。而且它有理论支撑——《跟枪学习完全攻略指南》：

> "有时候你有足够的能力阅读时会发现，**不动鼠标是跟踪小幅度变向的一种方式**。"

### 第 3 层｜变向瞬间：那 0.1–0.2 秒"什么都不做"

变向的瞬间，你的三个系统（眼、手、脑）会同时想做点什么。**全部压住。**

| 冲动 | 压住它，因为 |
|---|---|
| 眼睛想追过去 | 追=启动 0.1 s，正好追不上；不追=目标自己会回来 |
| 手想甩一下 | 甩=0.2 s 后到位，那时目标已经反向，你甩反了 |
| 脑想"它要往左了" | 这是**预判**。目标没反向你就先动 = 反向修正 = 相对速度翻倍 |

大东彦在《APEX 跟枪不是无数次的定位》（`BV1654y1d73x`，39 万播放）里把这件事拆成"手眼两个门槛"，你的问题明确在**眼睛那个门槛**：

> "是**有手眼两个门槛**的。眼睛的门槛，是你需要尽快地意识到目标进行了变向、**目标与你的准星脱轨了**。对于手的门槛，则是在于你意识到目标变向了之后…你还需要再次用平滑技巧进行下一段同向运动的平滑跟枪。"

他还给了这个场景最贴切的一个比喻：

> "跟枪的运动目标，在同向运动时可以看作是在**画一条线**…而用定位技巧强行打跟枪的，就是**目标在划线，而鼠标画点**——我们将线条拆分成无数个点来拟合目标运动轨迹。"

**你在用"点"拟合"线"，而这条线每 0.3 秒就折一次。** 点永远追不上折线。

### 第 4 层｜读速度：用血条，不用本体

- **血条**（4.4° 宽、饱和粉）→ 读方向和速度
- **黑色本体**（1.3° 宽）→ 确认判定
- **背景石墙缝**（大范围光流）→ 读"整体在往哪偏"

三个线索分工，别让眼睛在 1.3° 宽的黑条上做速度估计——那是这个场景最不可能完成的任务。

### 第 5 层｜参数层

1. **刷新率 ≥ 144 Hz**。大东彦在 `BV1654y1d73x` 里明确说："为了更好的看清并阅读运动目标，**144 Hz 以上刷新率的显示器基本上是必须的**。" 目标变向 2–3 次/秒，60 Hz 下每个单程只有 20–30 帧。
2. **FOV**：这个场景目标在近处（高 5.3°），FOV 越低目标越大越好读。别用 120+。
3. **准星**：用**小、亮、无遮挡**的准星（如小点）。目标只有 1.3° 宽，大准星会把它盖住。
4. **显示器距离**：大东彦提到他用 24 寸时距离只有 15 cm，"为了在玩一些竞技游戏的时候有足够好的专注度"。距离越近，目标张角越大——但这个场景目标本来就大，**优先保证"眼睛不累"**，别硬凑。

## 五、反面意见

**① "眼睛反应不过来，是不是该练动态视力？"——不该。**
Palidis 2017 的结论是 DVA 由"眼位误差 / 平滑度 / 抑制反向跳视"三个**策略因子**决定；大东彦直接说"没有什么能单独提高动态视力的方案"。**练 DVA 的最好方式就是把这个场景的眼动策略改对**，而不是去做眼保健操式训练。

**② "眼睛锁中心会不会漏掉目标？"——不会，因为你不需要"看见它"，只需要"它在准星上"。**
目标扫出中心区时你确实看不清它——但那段时间你本来就打不中。**把注意力集中在能打中的那 60–70% 时间上，比全程紧张有效得多。**

**③ "不动鼠标怎么可能跟得上？"——WR 的相机速度就是 0 px/s。**
这不是理论，是逐帧测出来的。当然"0"是近似——他的相机有极小幅度的修正（<1 px/帧），但**净位移几乎为零**。这个场景不需要你转身。

**④ "官方说 Raspberry 版加了 jumps，是不是要额外练垂直跟枪？"**
本次测量的两个窗口里目标高度稳定在 53–56 px，没有观察到明显跳跃。**jumps 是偶发事件，不是主要难点**；主要难点仍然是水平往复的频率。如果你实际打的时候觉得跳跃是主因，告诉我，我再单独测。

**⑤ "命中率 70% 已经很高了"——不。**
WR 是 70.65%，中位数是 6,999/18,003 = **38.9%**。**70% 是天花板，不是及格线。** 别拿"我命中率 70%"当自己已经到位的证据——要看你打的是哪个变体、多少分。
