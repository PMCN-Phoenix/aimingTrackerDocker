## 一、结论先行

### 1.1 这个场景是什么（官方机制回源）

官方描述（作者 tam 原文，Steam 创意工坊 **id 2183788318**）：

> "Small regenerating dots **wiggle back and forth** around you, **0.5s ttk**, **up to 1s to regen to full**, **starts regening 0.3s after going off target**."

拆成三个数字：

| 参数 | 值 | 含义 |
|---|---|---|
| **TTK** | **0.5 s** | 满血目标需要 0.5 秒的伤害 → 伤害速率 = **2 HP/s**（以"满血"为 1） |
| **回满时间** | **1 s** | 从 0 回到满血需要 1 秒 → 回血速率 = **1 HP/s** |
| **宽限** | **0.3 s** | 离开目标 0.3 秒后才开始回血 |

**这三个数字合起来，决定了这个场景的全部难度：**

> **回血速度 = 伤害速度的一半。你每掉线 1 秒，需要 2 秒才能把血补回来。**

这不是"稍微不准"的场景，这是**"不准就负收益"**的场景。

### 1.2 抖动在这个场景里到底值多少钱

设你在目标上的时间占比为 `p`（0~1），则净伤害速率：

```
净伤害速率 = 2p − (1−p)·1 = 3p − 1        （单位：满血/秒）
打死一个目标所需的「伤害时间」= 1 / (3p − 1)
```

| 在目标上时间占比 p | 伤害时间 | 相对理论值(0.5s) |
|---|---|---|
| 0.75 | 0.80 s | 1.6× |
| 0.609（本片实测） | **1.21 s** | 2.4× |
| 0.50 | 2.00 s | 4.0× |
| 0.40 | 5.00 s | 10× |
| 0.35 | 20.0 s | 40× |
| **0.333** | **∞** | **永远打不死** |

> **⚠️ 硬地板：当你在目标上的时间低于 1/3，回血就超过了你的伤害。你可以一直开枪，目标永远不死。**

这就是为什么"抖"在这个场景里感觉特别绝望——它不只是让你打偏，它让你**打不死**。

**实测验证（两个完全独立的来源对上了）：**

50 杀档参考录像（MattyOW，排行榜 #5，60 s，Kill 50 / KPS 0.8）：

| 来源 | 数值 |
|---|---|
| 结算面板 Accuracy | **2917 / 4723 = 61.8%** |
| 逐帧像素测「最近目标 < 20 px 的帧占比」 | **60.9%** |
| ROI 法测「目标离准星 < 20 px」 | **59.7%** |
| 面板 Avg TTK（= 1/KPS，击杀间隔） | **1.197 s** |
| 模型「伤害时间」（p = 0.609） | **1.21 s** |

像素测量和结算面板差 **2 个百分点**（61.8% vs 60.9%）；模型算出的伤害时间 1.21 s 与面板击杀间隔 1.197 s **差 1% 以内**。

> **注意这里的含义**：面板 Avg TTK 是「击杀间隔」（= 1/KPS），它 = 伤害时间 + 找目标/切目标时间。
> 两者几乎相等 → **这个玩家的切换开销 ≈ 0，他从不空窗**。这本身就是一条结论：**顶尖玩家不是打得更准，是"从不停止输出"。**

作为对照，40 杀档（另一个变体、另一个地图，90 s，Kill 40 / KPS 0.668 / Accuracy 2252/3051 = **73.8%** / Avg TTK **1.497 s**）：

| 项 | 50 杀档 | 40 杀档 |
|---|---|---|
| Accuracy | 61.8% | **73.8%（更高）** |
| 面板 Avg TTK | 1.197 s | 1.497 s（更长） |
| 模型伤害时间 | 1.21 s | 0.82 s |
| **切换/空窗开销** | **≈ 0 s** | **≈ 0.68 s** |

> **命中率更高的人，效率反而更低**——因为他每次击杀后要空窗 0.68 秒去找下一个目标。
> **在这个场景里，"准"的收益远小于"不停"的收益。**

### 1.3 关键发现：顶尖玩家的"抖"里几乎没有生理性震颤

这是本次调研最重要的一条，也是**反直觉**的。

我把 50 杀档录像逐帧跟踪（准星固定在屏幕正中 (960,540)，所以「目标屏幕坐标 − 屏幕中心」就是玩家此刻的偏差 e），然后在**已经贴住目标**（|e| < 20 px）的连续段里做高通（>4 Hz）和频谱：

| 量 | 值 |
|---|---|
| 贴身帧占比 | 59.7 ~ 60.9%（对上面板 61.8%） |
| 贴身时 \|e\| 中位 | **9.4 px**（点半径只有 **8.2 px**） |
| 手抖 RMS（>4 Hz 高通） | **3.31 ~ 4.10 px = 0.25 ~ 0.31°** |
| 抖动峰峰值 P90−P10 | **9.6 px = 0.72°** |
| 频谱峰值频率 | **1.88 Hz** |
| 0.5–3 Hz 能量占比 | **64.5 ~ 84.2%** |
| 3–8 Hz | 8.1 ~ 9.2% |
| **8–14 Hz（生理性震颤带）** | **1.1 ~ 5.0%** |
| 14–28 Hz | 0.2 ~ 8.2% |

> **结论：一个排行榜前五的玩家，他的"抖"里 8–14 Hz 的生理性震颤只占 1~5%。**
> **他的"抖"几乎全部是 1.88 Hz 的成分——也就是目标本身的摆动频率。**

换句话说：**你感觉到的"抖"，不是你的手在颤，是你的手在跟一个 1.9 Hz 的往复、并且每次反向都跟不上。**

### 1.4 主结论

> **"手腕不灵敏"不是手腕坏了，是你在让手腕干一件它结构上干不了的活：用同一个关节，在 0.26 秒内完成"减速—反向—再加速"。**

目标每 **0.53 秒**来回一次（1.88 Hz），也就是说**每 0.26 秒就要一次"零速反向"**。腕关节完成一次反向切换的机械时间常数在 0.1 s 量级——**占掉半周期的 38%**。所以腕部跟这个频率，必然是"过冲 → 回补 → 再过冲"，这就是你看到的抖。

而正确做法（下面第三节）是：**腕不做这个往复，腕只负责"停"；往复交给"不动"。**

B站 35.4 万播放《中文互联网最好的瞄准发力教学》把这件事说得比任何术语都直接：

> "**当你的手掌对鼠标施加了太多的下压力**，以整只手接触鼠标垫的部分，以及鼠标与地面之间的摩擦力激增，并与下压力产生对抗，**很容易让鼠标的滑动与手部的滑动都变得干涩卡顿**。"

而同主题的《一瞄准就手抖？你不是枪法差，是控鼠发力错了》（54.6 万播放）下面 165 赞的评论，几乎是你症状的逐字复述：

> "我鼠标握姿，就是整个手都覆盖鼠标上，这应该是趴握吧？**我手腕这块会一直蹭着鼠标垫，导致我静步排点预瞄特别抖**。就是别人预瞄，准星平移拉过去，特别稳，丝滑，赏心悦目，**我就又抖又颤，因为我手腕那块磨鼠标垫**……我试下让手腕悬空，那确实丝滑了，但是直接不会玩了。"

**"不灵敏"和"抖"是同一个原因的两种说法：静摩擦。** 要动它得先克服静摩擦（所以不灵敏），一旦克服就"弹"过去（所以抖）。

## 二、机制层：为什么"用腕去跟"在这个场景必然抖

### 2.1 目标每 0.53 秒来回一次 —— 正好在腕关节的"反向死区"

逐帧测出的相对运动主频 **1.88 Hz**，即一个完整往复 **0.53 s**，半周期 **0.26 s**。

人做小幅度往复运动时，**每个半周期都要经历一次"减速到零 → 反向加速"**。这不是"匀速移动"，而是每 0.26 秒一次完整的加减速循环。

| 环节 | 典型耗时 | 占半周期(0.26s) |
|---|---|---|
| 视觉确认"它反向了" | 0.15–0.25 s | 58–96% |
| 肌肉张力切换（主动肌→拮抗肌） | 0.05–0.10 s | 19–38% |
| 实际位移完成 | 剩余 | — |

**这两个延迟加起来就已经超过半周期了。** 所以你的手永远在"追上一段"——上一段还没追上，下一段已经开始了。

这和 Q004.10（Centering II 180 端点同步）是同一个物理：**"停止不是一个动作，是一个已经完成的状态。"** 只不过那里是"停不下来"，这里是"反向不过来"。

### 2.2 一个 TTK 里，目标要反向 4~5 次

- 击杀间隔 **1.197 s**（实测 Avg TTK = 1/KPS；50 杀 / 60 s）
- 目标摆动 1.88 Hz → 1.197 × 1.88 = **2.25 个完整往复 = 4.5 次反向**

> **每打死一个目标，你有 4~5 次机会把它跟丢。**
> 50 杀 / 60 s = 每 1.2 秒一个目标 → **你每分钟要处理大约 225 次反向。**

这就是为什么这个场景"一直有抖动"——不是偶发，是结构性的：**反向事件的密度超过了腕关节的处理带宽。**

### 2.3 生理性震颤：8–12 Hz，它是"噪声"不是"振荡器"

关于手抖，最常被误解的一点：**震颤不是可以"练掉"的节律，它是神经噪声被肢体机械滤波后的产物。**

**Vernooij, Lakie & Reynolds 2015**（J Neurophysiol 113:647）用随机机械扰动和随机电刺激，在**完全放松**的被试身上重建出了与生理性震颤**几乎完全相同**的频谱——包括 8–12 Hz 和 20–25 Hz 两个峰；在**临床去传入**（没有牵张反射）的病人身上结果也一样。结论：

> "both typical physiological finger tremor frequencies can be reproduced by random artificial input; **neither requires synchronized neural input**… mechanical resonance could generate both dominant frequency peaks."

**含义**：你不能靠"练稳定"消除震颤，因为它是噪声 + 共振。你只能做两件事：
1. **降低噪声源**（张力、发力大小、疲劳、咖啡因）
2. **改变共振特性**（握法、支点、质量、摩擦）

**Elble & Randall 1976**（J Neurophysiol 39:370）找到了 8–12 Hz 的源头：运动单位的**双放电**（double discharge，8–30 ms 的短间隔与 60–90 ms 的长间隔交替），在 17–22 spikes/s 的运动单位上最明显。**这是"用力"直接调制震颤的解剖学通路。**

**Vaillancourt & Newell 2000**（Clin Neurophysiol 111:1792）进一步确认：8–12 Hz 由中枢驱动、**幅度对载荷不敏感**；但 40 Hz 带的相对功率随**力**增大而增大。也就是说——**你越用力握，高频成分越多。**

### 2.4 越用力越抖：噪声正比于信号

**Harris & Wolpert 1998**（Nature 394:780）提出运动控制的统一理论：

> "the neural control signals are corrupted by noise **whose variance increases with the size of the control signal**."

**含义**：手部抖动幅度 ∝ 你发出的运动指令大小。

这条定律解释了你所有的体感：
- 慢慢挪 → 抖得小
- **急着追 → 抖得大**
- 甩完立刻急停 → 抖得最大（因为急停本身就是一次大指令）

**推论：在 1.88 Hz 的往复里"用力追"，是在用最大的指令去做最精细的活——噪声必然最大。**

### 2.5 静摩擦：不灵敏和抖是同一个物理现象

鼠标垫是布面（或混合面），静摩擦系数 **明显大于** 动摩擦系数。这个差值造成 **stick-slip（黏滑）**：

```
手施加力 F
  F < 静摩擦阈值  → 鼠标不动（你感觉"不灵敏"）
  F > 静摩擦阈值  → 鼠标突然滑动，且因为动摩擦更小，加速度更大（你感觉"弹过去"）
  → 力回落 → 又卡住 → 又弹
```

**这是一个自激振荡（极限环），频率由"手-鼠标-垫"系统的刚度/质量/摩擦差决定，典型落在 2–10 Hz——正好覆盖目标摆动的 1.88 Hz。**

而静摩擦阈值正比于**正压力**。正压力来自哪里？

| 正压力来源 | 怎么减小 |
|---|---|
| 手掌压在鼠标上 | 手心悬空 / 减轻下压 |
| 手腕蹭在鼠标垫上 | 抬腕 / 腕部不接触垫面 |
| 鼠标本身重量 | 换轻鼠（<60 g） |
| 鼠标垫表面太"涩" | 换更滑的垫（速度垫） |

B站《中文互联网最好的瞄准发力教学》（35.4 万播放）把这条链路讲全了：

> "**当你的手掌对鼠标施加了太多的下压力**，以整只手接触鼠标垫的部分，以及鼠标与地面之间的摩擦力激增，并与下压力产生对抗，**很容易让鼠标的滑动与手部的滑动都变得干涩卡顿**。"

**"干涩卡顿"就是 stick-slip 的体感描述。**

### 2.6 一个关节干两件事：腕的"反向延迟"

《中文互联网最好的瞄准发力教学》里还有一段，直接命中"手腕不灵敏"：

> "**如果手指无法参与发力，那么很多时候手腕就需要同时承担一次定位与微调两个任务。手腕需要经历两次反方向的移动，同一个关节的两次反向移动之间，必然存在的延迟。**"
>
> "可能手不同部位肌肉的张力预算都是有限的，**如果你把多个任务都交给手腕，极易导致其过度紧张失控**，它就会出现一种……难以控制的感觉。"

**"定位"和"微调"方向相反**：定位是往前推，微调是往回拉。同一个关节连做两次反向，中间必须过一次"速度归零"。

**而这个场景要的是：定位（切目标）→ 微调（贴住）→ 反向（跟摆动）→ 反向（再跟摆动）…… 一个关节连做 4 次反向。**

### 2.7 杠杆比：腕动 1°，鼠标走多远

手握点到鼠标传感器的水平距离约 **5–7 cm**。腕关节转动 θ 时，传感器位移 ≈ r·θ：

| 腕转动 | 传感器位移（r=6cm） | 在屏幕上（按 800eDPI 折算） |
|---|---|---|
| 0.1° | 0.10 mm | ~2 px |
| 1° | 1.05 mm | ~20 px |
| 3° | 3.14 mm | ~60 px |

**腕关节最小可控角位移受前臂肌群张力波动限制，大约 0.3–0.5°**——对应屏幕 **6–10 px**。

而目标的点半径只有 **8.2 px**。

> **腕关节的"最小可控步长"约等于整个目标的半径。用腕做微调，等于用一把刻度 8 px 的尺去量 8 px 的东西。**

这就是"不灵敏"的定量解释：**不是手慢，是分辨率不够。**

## 三、怎么打：五层，从最有效到最次要

### 第 1 层｜换支点：微调用掌根，大甩用小臂（最高优先级）

《中文互联网最好的瞄准发力教学》给出的"支点三档"，是这一层最清晰的操作说明：

| 指尖张力 | 支点 | 用途 |
|---|---|---|
| **1–2 成力** | **掌根** | **微调**（就是这个场景要的） |
| 3–5 成力 | 大鱼际 / 小臂 | 平滑跟枪、抬腕 |
| 6 成以上 | 小臂（长杠杆） | 大甩、切目标 |

> "在 1~2 成力时，你的支点是掌根，**我们在进行微调动作时，往往使用这个支点来进行移动**。"

**你现在的问题几乎可以确定是：用 6 成力的小臂支点去做 1–2 成力的活。**

具体动作：
1. 切目标时：指尖加紧（6 成），用小臂甩过去；
2. **目标一进入准星附近，立刻松到 1–2 成**，支点换到掌根；
3. 之后的摆动，**只用掌根那一点点位移去跟**，小臂完全不动。

### 第 2 层｜张力：永远不要"零张力"，也不要"满张力"

同一个视频里最关键的一句反直觉结论：

> "如果我们想要瞄得越准，手指就应该越放松吗？**我的答案是否定的。** 因为如果你持续处于一个过低的张力，你的大部分肌肉会处于一个未激活的状态，**等到需要用时再激活，也许就已经来不及了**。所以在大部分情况下，你的指尖张力需要提前进入一个 1~2 成的紧绷状态。"

**"提前"是关键词**——张力要在目标出现之前就到位，不是看到目标才发力。**看到才发力 = 大指令 = 大噪声（Harris & Wolpert）。**

### 第 3 层｜摩擦：把"手腕蹭垫"这个动作删掉

按 2.5 节的链路，逐个排查：

| 检查项 | 合格标准 | 不合格的表现 |
|---|---|---|
| 手腕是否蹭在垫上 | 腕部**悬空**或仅轻触 | 抬腕后立刻变丝滑 → 就是它 |
| 手心是否压死鼠标 | 手心**悬空**（指握/抓握） | 掌根发红、鼠标垫上有汗渍 |
| 鼠标重量 | < 70 g | > 80 g 时微调明显吃力 |
| 鼠标垫 | 速度垫 / 表面顺滑 | 布垫起毛、有汗渍、边缘翘起 |

B站 165 赞评论的实测结果就是最好的对照实验：**"我试下让手腕悬空，那确实丝滑了，但是直接不会玩了。"**
——前半句证明原因找对了，后半句说明**需要重新建立支点，不是一天的事**。

### 第 4 层｜打法：不要"追"摆动，要"守 + 等"

这是本场景特有的、也是最能立刻涨分的一层。

**因为你不可能跟住 1.88 Hz 的往复（第 2.1 节），所以不要试图跟。**

| 现在 | 改成 |
|---|---|
| 目标往左，准星往左 | 目标往左，**准星不动** |
| 目标往右，准星往右 | 目标往右，**准星不动** |
| 目标扫出准星 → 追 | 目标扫出准星 → **等它回来** |
| 一直微调 | **只在它经过准星时开火** |

这和 Q004.11 的结论完全一致（那里是 WR 相机速度 = 0 px/s），只是这里的理由不同：**那里是眼睛追不上，这里是手腕反向不过来。同一个解法：不动。**

**判断标准**：如果你的准星在目标左右各画一条"轨迹"，说明你在追；如果准星基本停在一个位置、目标在它两侧扫，说明你做对了。

### 第 5 层｜参数层

1. **eDPI**：本场景目标只有 8.2 px 半径。eDPI 过高 → 腕部 0.3° 的抖动就是 10 px；eDPI 过低 → 需要大位移，腕关节被迫进入"多次反向"模式。**建议 800eDPI 附近做基准，上下各试一档。**
2. **回报率 1000 Hz + 关闭鼠标加速/平滑**（Windows"提高指针精确度"必须关）。
3. **刷新率 ≥ 144 Hz**：目标 1.88 Hz 摆动，60 Hz 下每个半周期只有 32 帧。
4. **准星**：小点或小十字。目标半径 8 px，大准星会把它盖住，你反而看不见自己在抖。

## 四、训练处方（15 分钟）

### Drill 1｜掌根支点微调（4 分钟）★ 最有效

- 进场景，**小臂完全不动**，只用掌根那一点位移
- 手指张力保持 1–2 成，**不要松到 0**
- 目标扫出准星就让它扫出去，不追
- 目的：把"微调=腕/臂动"改成"微调=掌根动"
- 前两轮分数会掉——正常，你在换一套执行器

### Drill 2｜张力扫描（3 分钟）

- 同一段 30 秒，分别用 1 成 / 3 成 / 6 成力打
- 记录三次分数
- 目的：让你身体自己发现"哪个张力在这个场景最稳"，而不是听别人说

### Drill 3｜抬腕（3 分钟）

- 手腕**完全离开鼠标垫**（悬空），只靠掌根/小臂支撑
- 如果完全不适应：先在垫子上贴一条低摩擦胶带，让腕部滑而不是蹭
- 目的：切断 stick-slip 的正压力来源

### Drill 4｜只打完整击杀（3 分钟）

- 规则：**一个目标没打死，绝对不许切下一个**；打死之后 **0.3 秒内必须开始打下一个**
- 理由（见 1.2）：伤害不能存。打一半就走，1 秒后它满血，你刚才的伤害全是白打
- 第二个理由：50 杀档的切换开销 ≈ 0，40 杀档是 0.68 s——**这 0.68 s 就是分数差**
- 目的：建立"承诺 + 不停"两个习惯

### Drill 5｜降级打基础（2 分钟）

| 场景 | 官方 id | 说明 |
|---|---|---|
| `tamTargetSwitch Control Initiate` | 2855599533 | 目标 **50% 更大** |
| `TamTargetSwitch Control Easy` | 2522496909 | 更慢 |
| `tamTargetSwitch Control Smaller Longer Strafes` | 2392789238 | 摆动更长（反向更少），但目标更小 |
| `tamTargetSwitch Smooth`（原版） | 2183788413 | 目标绕你转（不往复），先建立基础跟枪 |

### 收尾｜3 轮正式打（2 分钟）

记 `Kill / Accuracy / Avg TTK`。**只看 Avg TTK**——它把回血惩罚算进去了，是唯一反映真实效率的指标。

## 五、反面意见

**① "手抖是天生的 / 是不是手抖症？"——不是。**
生理性震颤人人都有（8–12 Hz），且 Vernooij 2015 证明它是噪声 + 机械共振，不是病。真正的病理性震颤（特发性震颤）频率更低（4–8 Hz）、幅度大一个数量级、影响日常动作。**你只是在"用大指令做精细活"。**

**② "换更低的灵敏度就不抖了"——半对，但会换来另一个问题。**
低 eDPI 让同样的腕部角抖动对应更少像素（抖动幅度下降），但**要求更大的关节位移**，于是"定位"和"微调"更可能落到同一个关节上（2.6 节）。B站高赞评论的实测："以前进行微调可以说根本就做不到，但凡动一下手掌就是直接准星漂移。"

**③ "手腕流 / 手臂流"——伪命题。**
东彦（《你真的会选择合适的鼠标握法吗》，58.4 万播放）原话：

> "手臂上不上桌子和你的坐姿、桌子相对高度差以及你的偏好有关，**手腕手臂流的不同选择，基本上是不会影响你瞄准水平的**。那么一定不要局限于你所谓的这个手腕、手臂流的这种划分方式，**真正的瞄准高手指会根据你的体质的不同，有效率的利用所有可利用的肌肉来进行瞄准**。"

**④ "多练就能稳"——练错方向会更稳地抖。**
如果每次练都在高张力下追摆动，你练的是"高张力下的追"，肌张力基线会越来越高。**先改支点和张力，再谈量。**

**⑤ "抖动 <0.3 秒不是免费的吗？"——对，但只在单次。**
官方给的 0.3 s 宽限是**每次脱离**都重新计时的。所以：
- 单次 0.2 s 的抖动 → **完全免费**
- 连续抖动、每次 0.4 s → **每次都按 2 倍计费**

**这意味着：把"长时间连续抖"改成"短促、干脆的几次脱离"，比"追求手完全不动"更现实、也更有效。**

**⑥ "官方说 Control 是 wiggle，Hard 还加了 bouncing，是不是要练垂直？"**
本次测量的两个窗口里目标 y 坐标稳定，没有明显垂直分量。**bouncing 只在 Hard 变体里**，你打的是 base Control，主难点仍然是水平往复。
