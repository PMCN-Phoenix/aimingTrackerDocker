> **用户问题原文**："在一个速率移动鼠标时候怎么实现匀减速，怎么实现的减速而不是制动这种突然停下"

## 〇、问题定位：这题和 Q007 是什么关系

**Q007 回答的是"停下来之后"**：为什么停完想微调时手僵住（张力释放时滞）。
**本题回答的是"停下来之前"**：移动过程中怎么让速度降下来，而不是到终点"撞停"。

两者是同一条因果链的上下游：**制动式急停正是 Q007"僵住"的上游病因**——你在终点主动收紧（或反向发力）的那一下，就是锁死微调肌肉的那一下。本题解决"怎么停"，Q007 解决"停完之后怎么动"。两份方案应配合执行。

## 一、结论先行

> **匀减速不是"在终点做的一个动作"，而是把"停止"从末端事件改造成全程事件**：启动时攒的张力在移动途中逐步泄掉，速度曲线因此成为斜坡而不是悬崖，最后一小段交给鼠标垫摩擦力和残余动量自然完成。制动式急停（终点收紧 / 反向发力 / 下压鼠标）是用共收缩强行"覆盖"运动系统自带的平滑减速程序，代价是肌电机械延迟（EMD）增大 + 微调肌肉锁死——这正是 Q007 的病因。

### 核心要点

1. **制动三禁忌**（晨曜 BV16eaA6bE9F 05:40-06:20）：①拉枪结束时主动再次紧绷手臂/手指（微调肌肉当场锁死）②下压鼠标增大摩擦制动（手腕手指紧绷 + 摩擦变化干扰微调）③抬鼠标悬空制动（停顿时间成本）。
2. **解法叫"卸力/泄力"**（晨曜 06:30-06:45）：启动时收紧肌肉没问题，但**在拉枪途中就让紧绷逐步释放**，配合垫子摩擦力自然停住——"不是到目标了再放松，是途中就开始卸"。
3. **减速是独立技能，不是启动的附带品**：甜糖把瞄准明确拆为**发力→减速→确认**三段（BV1eRm8YeEJx 00:16）；神经科学侧对应 **M1 运动皮层对加速与减速阶段分开编码**（Kadmon Harpaz, Hatsopoulos, Flash 2019, PMC）——减速值得单独练。
4. **减速方式有三种，代价各不同**（甜糖 BV1eRm8YeEJx 00:49-05:51，详见第三节对比表）：收紧小臂（一次定位准但锁死）、下压力（不锁死但垂直力干扰水平发力）、卸力（社区最优解）。
5. **减速的本质是"张力转移"而不是"张力增加"**：跟枪变向时张力从手腕转移到前臂（MattyOW×Scucchi Ep.4），支点到极限就换支点而不是硬撑（克礼无明）。
6. **手腕/手臂任务分离有两种模式**（xen2 中字，Spooky 示范）：臂保持张力做平滑 + 腕做变向拨动；或臂做高张拨动 + 腕保持中立做精跟——两种都要练，游戏里会交替出现。
7. **目标导向的平滑**（rawinput.net/Bardoz 体系）：Zeonlo 对**每个目标**都"decelerates onto the target"，平滑到能把 2-3 个目标连成一个动作流过；Minigod：接近目标群时用平滑进入代替剧烈甩入，"慢一点，但 less jarring"。
8. **⚠️ 命名冲突警告**：**软件的"鼠标平滑"（Mouse Smoothing，引擎/驱动插值，要关闭）与手部的"平滑减速"（Smoothness，要练）是两个同名不同物**。B站《关闭鼠标平滑》（BV1gdZmBYEoa，43 万播放）讲的是前者，与本题无关。

## 二、机制层：为什么"制动"错、"匀减速"对

### 2.1 制动的生理代价（本地循证）

本地 DR 循证报告（`FPS瞄准科学机制的硬核循证检验与八周计划独立重构.md` 判定表 #12）已核实：

> 紧张（大力捏紧鼠标）不能提高神经传导——**过度紧张导致严重共收缩（co-contraction），大幅增加肌电机械延迟（EMD），使肌肉在启动和制动时发生"粘滞"**。

翻译成操作语言：制动那一下的共收缩让你**整块前臂同时绷死**，之后无论想启动微调还是二次定位，都要先等共收缩卸掉（Q007 的"张力释放时滞"）——所以制动式急停的代价从来不在"停"本身，而在"停完之后"。

### 2.2 减速是运动系统的默认程序，制动是人为覆盖它

学术构念（标注回源状态）：

| 构念 | 内容 | 对本题的意义 | 回源状态 |
|---|---|---|---|
| **两成分模型**（Woodworth 1899，Elliott 等综述） | 快速瞄准 = 初始脉冲（爆发段）+ 当前控制（减速/修正段）；目标难度越高，减速期占比越长 | "减速期"是一个正式命名的动作阶段，训练应聚焦于此 | 教科书构念，本轮未回源原文（WebSearch 故障），待补 |
| **最小急动度**（Flash & Hogan 1985） | 自然够物动作的速度曲线呈钟形、加速度连续变化（jerk 最小化） | **匀减速是运动系统的默认偏好**——你不需要"制造"平滑，只需要不破坏它 | 同上，待回源 |
| **三相 EMG**（Hannaford & Stark） | 快速点动作 = 主动肌爆发 → 拮抗肌制动脉冲 → 主动肌再增强 | 健康的停止=拮抗肌**分级脉冲**；锁死=主动/拮肌**同时收缩**（共收缩）——两者是不同的神经程序 | 同上，待回源 |
| **M1 分离编码**（Kadmon Harpaz, Ungarish, Hatsopoulos, Flash 2019, *Movement Decomposition in the Primary Motor Cortex*） | 运动皮层对加速段与减速段**分开编码** | 减速有独立的神经表征——"单独练减速"有神经科学依据 | ✅ 本轮 PMC 已回源 |
| **减速调控受损的实证**（Inzelberg 1995，肌张力障碍患者） | 患者上肢速度 profile **对称性降低**（减速段形态异常） | 减速段形态是可测量、可受损、可训练的运动质量指标 | ✅ 本轮 PMC 已回源 |

## 三、实现匀减速的四条社区路径（附操作定义）

### 路径一：提前卸力（晨曜，B站共识解）

1. 启动：为速度收紧肌肉——**这一步是对的，不用改**
2. 途中：紧绷**逐步**释放（不是留到终点一次性放）
3. 末段：残余动量 + 垫子摩擦力完成最后停止
4. 终点验收：手腕手指处于"预开火状态"（微微绷着、蓄势待发），而不是锁死状态

### 路径二：选对减速方式（甜糖三方式对比，BV1eRm8YeEJx 00:49-05:51）

| 减速方式 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 收紧小臂肌肉减速 | 一次定位精准 | **肌肉锁死、二次三次衔接差、抖动** | 仅限"停完就打、不再微调"的场景 |
| 下压力减速（压鼠标增大摩擦） | 肌肉不锁死、可多次定位 | 难控制、垂直下压力干扰水平发力 | 趴握用户的次优解，需专门练控制力 |
| 卸力减速（途中泄力） | 停得稳 + 肌肉相对放松、利于后续瞄准 | 手感最难上手，需要专门训练 | **默认推荐** |

### 路径三：张力转移与支点切换（MattyOW×Scucchi + 克礼无明）

- 变向持续时：先手腕（尽量久）→ 到伸展极限前把张力**转移**到前臂继续跟，而不是全身一起加紧
- 任何支点（腕/肘/肩）到运动极限就必须换，硬撑会引发代偿（耸肩、压腕）
- 重置鼠标的最佳时机是**机器人即将变向时**（此时动作角度本来尴尬）——Scucchi 的垫子空间管理

### 路径四：目标导向的平滑进入（Bardoz 体系 / rawinput.net）

- Zeonlo：对每个目标"decelerates onto it"，把 2-3 个近目标当 cluster 连续流过——代价是直接 flick 不是最快，且要求微调/确认极快
- Minigod：接近目标群用平滑移动代替剧烈甩入，"更慢，但 less jarring"，让你专注射击时机
- 与 Bardoz 三段式兼容：flick（前臂爆发直线）→ microcorrection（更窄更平滑的调整）→ confirmation，第一段到第二段的过渡**本身就是本题的减速段**

## 四、训练方案（2 周专注版，可与 Q007 方案叠加）

### 场景池（平滑度即分数，天然反馈）

| 场景 | 训练什么 |
|---|---|
| Kovaak's Smoothbot 系列 | 匀速-变速平滑跟踪（VDIM 平滑日自带） |
| Smoothness Trainer Robot | 原始平滑（raw smoothness），画木啄眉（世界前 0.6%）用于对照 |
| Aimbeast Smooth V2 | 平滑跟枪入门（难度分级友好） |
| vertical smoothness / popcorn 垂直平滑 | 垂直方向减速（手腕关节不擅长垂直，必练） |
| PGTI / PreciseOrb（Q007 已引） | 变速目标的跟随与减速 |

### Drills

1. **拉枪制动不开枪**（晨曜法，每天 warm-up 3 组×10 次）：靶场连续拉枪，最后一次刻意停住不开枪，感受"预开火状态"——如果手腕是僵的，说明途中没卸力。
2. **减速方式 A/B 自测**（甜糖法）：同一场景各打 50 次——A 组终点收紧小臂、B 组途中卸力。对比：二次定位衔接成功率、准星晃动幅度（录屏 240fps 回放看终点抖动）。
3. **隔离训练**（xen2/Spooky 法）：仅手臂的垂直平滑场景（手腕锁死）；仅手腕的水平精跟场景（手臂锁死）。各自建立"这块肌群独立负责减速"的手感。
4. **握压自检**（钚荟画法）：鼠标背 7 分 / 侧面 6 分 / 按键 5 分的力度框架 + 滑动时"手心轻微锁定感"，下压力不过高（"过高下压力让瞄准地震"）。

### 灵敏度注记

xen2 指出更低灵敏度更平滑——但你已在 71cm/360 极低敏，这是既成事实。**你的卡点不在灵敏度，在减速程序**（路径一/二）。

### 验收指标（4 项，2 周复盘）

1. Smoothbot 类场景分数周环比（+5% 即有效）
2. 240fps 录屏：flick 终点后 300ms 内准星晃动幅度（主观分级 1-5，应下降）
3. 二次定位衔接成功率（A/B 自测中的 B 组胜率）
4. 排位体感：转火"停-调"衔接是否还出现 Q007 的僵住（出现频次下降）

## 五、常见错误对照表

| 错误 | 后果 | 纠正 |
|---|---|---|
| 终点再紧绷一次"刹住" | 微调肌肉当场锁死（Q007 病因） | 途中卸力，终点只留"预开火状态"的微张力 |
| 下压鼠标刹车 | 手腕手指紧绷 + 摩擦变化干扰微调 | 垫子摩擦已经够用，不要手帮垫子刹车 |
| 抬鼠标悬空调整后放回 | 停顿时间成本天然存在 | 仅限垫子空间耗尽的场景；平时重置放在目标变向时 |
| 手腕锁死后硬撑着继续跟 | 代偿（耸肩/压腕），两个物理运动相悖（克礼无明） | 换支点：腕→肘→肩 |
| 用手腕做微调（应为手指） | 微调永远过头（姚大韬） | 手臂支点 + 手腕悬空连接手指 |
| 把"关闭鼠标平滑"当成本题解法 | 关的是软件插值，与手部减速无关 | 分清两个同名概念（见核心要点 8） |

## 六、反面意见与边界（照例单列）

1. **姚大韬（25.9 万播放）**："完美的右手平滑瞄准没有意义，手指才是微调的关键。"——解读：平滑是**服务微调的手段**而非目的；为平滑而牺牲启动速度本末倒置。本题的回应：卸力路径恰恰以"终点预开火状态"（可快速启动）为验收，与该意见兼容。
2. **Zeonlo 流派的代价**（rawinput.net 明说）：decelerate-onto-target 让直接 flick 不再最快，且逼出极快的 micro + confirmation——**低密度远距离目标时，爆发优先于平滑**（xen2 也提到顶尖选手为速度会增加张力）。
3. **场景局限**（沿 Q007 结论）：Kovaak's 大部分平滑场景是规则模式（直线/匀速机器人），实战中的减速发生在杂乱轨迹上——场景练的是程序，实战练的是触发时机。
4. **学术侧未决**：三相 EMG / 最小急动度 / tau 控制三个构念本轮未回源原文（WebSearch 故障），"匀减速是默认程序"的表述目前是**教科书级常识 + 社区多源一致**，置信度 B 而非 A。下轮补源后可升。
