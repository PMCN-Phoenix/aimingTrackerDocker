# 14-今日清单页面重设计文档

> 版本：v1（待核实）
> 日期：2026-10-20
> 范围：`/daylist/:daylistId`（`DaylistDashboard.jsx` + `ProgressTable` + `ComparisonTable` + `ExtraDaylistCard`）
> 不改：数据模型（除第 10 节列出的 2 处补字段）、Grafana 看板、VDIM 页面

---

## 0. 一句话

现在这个页面把**同一批场景列了两遍**（完成度一张表、目标对比一张表），要上下滚动才能把「打够没有」和「离下一档差多少」对起来。
重设计的目标是：**一行之内同时回答三个问题——轮数打够了吗、分数离下一档差多少、今天后段掉没掉。**

---

## 1. 背景与目标

### 1.1 为什么改

页面是从 Grafana 的 D 看板 1:1 还原过来的（见 `06-看板渲染设计文档`），Grafana 那边两块面板本来就是分开的，还原时把「分开」也一起还原了。
但 Grafana 面板是并列摆放、可各自调整高度的；Web 版变成上下两张表后，**同一批 14 个场景出现 28 行**，对照成本反而比 Grafana 更高。

### 1.2 目标（可验收）

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 不滚动就知道今天整体完成情况 | 首屏（1080p）内可见完成度环 + 达标项数 |
| G2 | 一个场景的所有信息在同一行 | 进度、目标、达成度、命中率、状态同行呈现 |
| G3 | 14 项清单在 1080p 一屏内看完 | 默认「卡片流」模式下无需滚动主区 |
| G4 | 能看出「今天后段有没有掉」 | 每行显示 首轮→末轮 的衰减百分比 |
| G5 | 目标线缺失时不留空列 | 非 Viscose 场景（如 Day9）显示「无基准」而不是一排 `-` |

### 1.3 非目标

- 不做移动端适配（桌面 1280px+ 优先）
- 不改 Grafana 看板
- 不改清单的数据模型（`aim_daylist` / `aim_daylist_meta` 结构不动）
- 不做清单编辑（编辑仍走 md 源文件 → `daylist_sync.py`）

### 2.1 顺手修掉的两个数据层 bug（本页直接受益）

| Bug | 现象 | 原因 | 修复 |
|---|---|---|---|
| 场景历史曲线永远空 | `GET /api/scenarios/{s}/history` 恒返回 `[]` | `_flux_history` 里写成 `filter(fn: (r) -> ...)`，Flux 要求 `=>`，语法错误被 `except` 吞掉 | 改 `=>`；实测 `1w2ts reload smallflicks larger` 60 天返回 29 个点 |
| `progress.label` 恒为空串 | 接口返回 `label: ''`，但 `/api/daylists` 里是「攻Blending」 | `label` 是 **tag** 不是 `_field`，`get_daylist_meta` 只遍历 `_field/_value`，tag 被丢掉 | 单独取 tag；实测 Day8→「攻Blending」、Day9→「Strafe Aiming 移动瞄准」 |

## 3. 数据契约（实测样本，2026-10-19/20）

设计必须落在**真实存在的字段**上。以下全部为实际抓取结果，不是设想。

### 3.1 接口清单

| 用途 | 接口 | 实测规模 | 本页是否必需 |
|---|---|---|---|
| 清单列表（下拉） | `GET /api/daylists` | 9 条（Day1–Day9） | ✅ 必需 |
| 清单进度（主数据） | `GET /api/daylists/{d}/progress` | Day9：14 行 | ✅ 必需 |
| 加练清单 | `GET /api/daylists/{d}/extras` | 当前 0 条 | ✅ 必需 |
| 清单+加练一次拿 | `GET /api/daylists/{d}/with-extras` | `{main, extras[]}` | ⭕ 可替代上两条（少一次请求） |
| 场景抽屉 | `GET /api/scenarios/{s}/popup?start_ts&end_ts` | 含 history 数组 | ✅ 必需 |
| 场景历史 | `GET /api/scenarios/{s}/history?days=&list=` | 29 点 | ⭕ 抽屉内已有 history，可不用 |
| 单场景轮数 | `GET /api/scenarios/{s}/rounds?start_ts&end_ts` | `{rounds: 4}` | ❌ 不用（progress 已有 done_rounds） |
| 基准全量 | `GET /api/bench/scenarios` | 39 条 | ❌ 不用（已并入 progress） |
| 感悟统计 | `GET /api/game-reflections/stats` | total 25 / 今日 0 | ⭕ 顶栏角标可选 |
| 更新数据 | `POST /api/data/update` | 跑 `update_all.py` | ✅ 必需 |

### 3.2 `GET /api/daylists` → `data[]`

```json
{ "daylist": "Day9", "label": "Strafe Aiming 移动瞄准", "run_date": "2026-10-14" }
```

> 只有三个字段。**没有** `items` / `rounds_total` —— 下拉里不能显示「14 项/55 轮」，要显示就得靠 progress 再查一次。

### 3.3 `GET /api/daylists/{d}/progress` → `data`

顶层字段（实测 Day8）：

| 字段 | 实测值 | 说明 |
|---|---|---|
| `daylist` | `"Day8"` | |
| `label` | `"攻Blending"` | 已修（原为空串） |
| `name` | `""` | 加练清单才有 |
| `type` | `"main"` | `main` / `extra` |
| `parent_daylist` | `""` | 加练才有 |
| `created_at` | `0` | 加练才有 |
| `run_date` | `"2026-10-08"` | |
| `exec_dates` | `"2026-10-08"` | 可多日，逗号分隔 |
| `start_ts` / `end_ts` | `1791388800` / `1791475199` | 本地日 00:00–23:59 |
| `items` | `8` | 项数 |
| `rounds_total` | `23` | 总轮数 |
| `rows` | 见下 | |

`rows[]`（实测 Day8 order=4）：

```json
{
  "order": 4,
  "scenario": "Air CELESTIAL No UFO Easier",
  "role": "主项",
  "required_rounds": 4,
  "done_rounds": 3,
  "status": "进行中",
  "today_score": { "score": 850.8, "accuracy": 45.4 },
  "bench": {
    "nextLine": 852.0, "pct": 87.6, "gapPct": 0.1,
    "rank": "Ermine", "subRank": "Puffin",
    "cat": "CONTROL TRACKING", "sub": "Blending",
    "achIdx": 3,
    "targets": [800.0, 817.0, 842.0, 852.0, 862.0, 873.0, 883.0, 889.0, 896.0]
  }
}
```

字段可用性判定：

| 字段 | 是否可空 | 空值场景 |
|---|---|---|
| `today_score` | ✅ 可 `null` | 该场景当天没打 |
| `today_score.accuracy` | ✅ 可 `null` | 该场景没有 hits/misses |
| `bench` | ✅ 可 `null` | 场景不在基准表里（Day9 的 14 项全部如此） |
| `bench.rank` / `subRank` | ✅ 可 `null` | 档位未定 |
| `bench.achIdx` | ✅ 可 `null` | 同上 |
| `bench.targets` | ✅ 可 `null` | 同上 |

> **关键**：`targets` 是 9 档阶梯（Lemming→…→最高档）的分值数组，`achIdx` 是当前所处档位下标。这两项是本轮新加进 progress 的，前端不用再单独请求 `/api/bench/scenarios`。

### 3.4 `GET /api/scenarios/{s}/popup?start_ts&end_ts` → `data`

```json
{
  "scenario": "1w2ts reload smallflicks larger",
  "today_score": { "scenario": "...", "score": 108.0, "accuracy": 99.1 },
  "bench": { "scenario": "...", "nextLine": 112.0, "pct": 33.3, "gapPct": 3.6,
             "achIdx": 5.0, "rank": null, "sub": null, "subRank": null },
  "reflections": [],
  "history": [ { "time": "2026-09-20T12:59:33Z", "score": 91.0, "scenario": "..." }, ... ]
}
```

> 注意 `popup.bench` **不含** `targets`（只有 `achIdx`）。抽屉里要画阶梯需自己按 `achIdx` + 阶梯数推，或复用 progress 行的 `bench.targets`（推荐：抽屉从父级把该行的 `bench` 传进去）。

### 3.5 数据缺口（需要后端补的字段）

| 缺口 | 现状 | 需要 | 影响模块 |
|---|---|---|---|
| **轮次衰减** | progress 只有 `today_score.score`（当日最大值），无首轮/末轮 | `rows[].round_stats: {n, first, last, best, drop_pct}` | 6.3 衰减列、6.2 汇总卡 |
| **实际执行时段** | 只有 `start_ts`/`end_ts`（整天 00:00–23:59），不是真实开练时间 | `rows[].first_ts` / `last_ts`，或顶层 `session: {start, end}` | 6.1 上下文条（显示「09:08–11:11 · 2h03m」） |

两处都在 `_get_window_scores()` 里顺手能算（它已经在扫窗口内的所有点），见 10.2。

## 4. 设计方向

### 4.1 核心思路：**双轨制**

每个场景一行，左边一条「轮数轨」、右边一条「分数轨」。两条轨是**不同维度**，以前被拆成两张表，现在并排：

```
轮数轨  ████████░░  3/4 轮        ← 打够了没有（训练量）
分数轨  ●────┼──   850.8 / 852   ← 离下一档差多少（训练质）
```

### 4.2 两种密度（可切换，默认卡片流）

| 模式 | 适用 | 单项高度 | Day9(14项) 总高 |
|---|---|---|---|
| **卡片流**（默认） | 日常练完复盘，一行看全 | ~64px | ~896px + 头部 ≈ 一屏 |
| **紧凑表** | 项数 > 12 或想快速扫 | ~36px | ~504px |

切换按钮放在上下文条右侧，选择存 `localStorage`。

### 4.3 视觉语言

- 保留 antd 浅色底（与其它页面一致），但主区改为**卡片 + 大留白**，去掉表格的竖线网格
- 主色沿用 `#1677ff`；**完成 = 绿 `#52c41a`**、**进行中 = 橙 `#fa8c16`**、**未开始 = 灰 `#bfbfbf`**、**衰减预警 = 红 `#ff4d4f`**
- 场景名用等宽字体（场景名多为英文 + 空格，等宽更易扫读）
- 数字右对齐、`font-variant-numeric: tabular-nums`，保证上下行位数对齐

## 6. 模块详细设计

### 6.1 ① 上下文条 `ContextBar`

| 元素 | 数据来源 | 缺失时 |
|---|---|---|
| 清单下拉 | `GET /api/daylists` → `daylist` + `label` | 只有一个清单时退化为纯文本 |
| 执行日 | `progress.run_date`（多日则 `exec_dates` 拆开显示） | 显示 `—` |
| 实际时段 | **待补** `session.start/end`（3.5） | 隐藏该段，不占位 |
| 密度切换 | 本地 state + `localStorage` | — |
| 刷新 | `refetch()` + `refetchExtras()` | — |
| 导出 Playlist | `POST /api/daylists/{d}/export-playlist` | — |

> **删掉 `DateRangePicker`**（P3）。它对主表完全无效，留着只会误导。抽屉里的时间窗用 `start_ts/end_ts` 自动带上，不需要用户选。

### 6.2 ② 汇总卡 `SummaryStrip`

四格，全部由 `progress` 现成字段算，不需要新接口：

| 格 | 计算 | Day9 实例 |
|---|---|---|
| 完成度 | `rows.filter(r => r.status === '已完成').length / rows.length` | 14/14 = 100% |
| 训练量 | `Σ done_rounds / rounds_total` | 55/55 |
| 达标项 | `rows.filter(r => r.bench?.nextLine && r.today_score?.score >= r.bench.nextLine).length`，分母为「有基准的项数」 | 0/0（无基准）→ 显示「无基准数据」 |
| 衰减预警 | `round_stats.drop_pct > 15` 的项数 + 最差值（**待补字段**） | 3 项，最差 −32.1% |

**降级规则**：`bench` 全为 null 时（Day9 情形），第三格显示「该清单场景不在基准表内」，不显示 `0/0`。

### 6.3 ③ 清单主体 `DaylistRow`（核心）

一行 = 一个场景。**卡片流**布局：

```
┌──────┬─────────────────────────────────────────────────────────────────┐
│  5   │ 主项   lgc3 Reborn Easy                          ⚠ 衰减 −32.1%  │
│ 序   │ 轮数  ████████░░  5/5 已完成                                     │
│ 号   │ 分数  ●────┼──────  18504 / 无基准   命中 26.8%   末轮 12567    │
└──────┴─────────────────────────────────────────────────────────────────┘
```

字段映射：

| 视觉元素 | 字段 | 空值处理 |
|---|---|---|
| 序号 | `order` | — |
| 角色 chip | `role`（热身/卡口/主项/巩固） | 空则隐藏 chip |
| 场景名 | `scenario` | — |
| 衰减标记 | `round_stats.drop_pct`（**待补**） | 无则隐藏 |
| 轮数条 | `done_rounds / required_rounds`，超 100% 封顶显示但标注「+N」 | `required=0` 视为 100% |
| 状态 chip | `status`（已完成/进行中/未开始） | — |
| 分数条 | `today_score.score` 在 `bench.targets` 9 档阶梯上的位置 | `bench=null` → 显示「无基准」灰字，条改为**只显示数值** |
| 目标值 | `bench.nextLine` | `null` → 「无基准」 |
| 达成度 | `today_score.score / bench.nextLine` | `null` → 不显示 |
| 命中率 | `today_score.accuracy` | `null` → `—` |
| 末轮 | `round_stats.last`（**待补**） | 无则隐藏 |

**紧凑表**布局：同样的列，但压成一行，衰减/末轮收进 tooltip。

### 6.4 档位阶梯 `TierLadder`（内嵌在分数轨）

用 `bench.targets`（9 个值）+ `achIdx` 画一条 9 段的细阶梯，当前分落点用三角标记：

```
Lemming  Hare  Ermine  ...                                    最高档
  800    817   842   852   862   873   883   889   896
  ──●────●─────●─────▲─────●─────●─────●─────●─────●
                  850.8 ↑ 当前（第 4 档，距下一档 1.2 分）
```

- 已过档位：实心
- 当前档位：主色
- 未到档位：空心灰
- `targets` 为 null → 整个阶梯不渲染

### 6.5 ④ 加练区 `ExtrasSection`

- 移到主表**之后**（P8），默认折叠，标题带计数
- 展开后每张 `ExtraDaylistCard` 复用同一套 `DaylistRow`，只是顶部多一行「父清单：Day9」
- 「新增加练」按钮保留在折叠头右侧
- 数据：`GET /api/daylists/{d}/extras`（返回带完整 `rows`，实测 `queries.py:511` 会调 `get_daylist_progress_data`）

### 6.6 ⑤ 场景抽屉 `ScenarioDrawer`

用 antd `Drawer`（右侧 480px）替换现在的 `Modal`，理由：不遮挡主表，可以边看主表边看详情。

| 区块 | 数据 |
|---|---|
| 头部 | 场景名 + 角色 + 状态 |
| 当日成绩 | `popup.today_score`（score / accuracy） |
| 基准档位 | `popup.bench`（nextLine / gapPct / rank / subRank）+ 阶梯（从父行 `bench.targets` 传入） |
| 历史曲线 | `popup.history`（ECharts 折线，x=time, y=score；已修好，实测 29 点） |
| 相关感悟 | `popup.reflections[]`（空则显示「该场景还没有感悟」+ 快捷跳转） |

### 6.7 空态与错误态

| 场景 | 表现 |
|---|---|

### 10.2 本轮待做（依赖确认后实施）

| 改动 | 位置 | 影响面 |
|---|---|---|
| `rows[].round_stats = {n, first, last, best, drop_pct}` | `queries._get_window_scores` | 只增字段，向后兼容 |
| `data.session = {start, end, duration_min}` | `queries.get_daylist_progress_data` | 同上 |

`round_stats` 计算口径：

```
n        = 该场景在窗口内的轮数
first    = 时间上第一轮的 score
last     = 时间上最后一轮的 score
best     = 窗口内最大 score（== today_score.score）
drop_pct = (last - best) / best * 100   # 负数=掉分
```
