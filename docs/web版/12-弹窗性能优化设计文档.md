# 弹窗加载性能优化设计文档

## 1. 问题

当前场景详情弹窗加载太慢，主要原因：
1. 两个串行 API 请求（popup 数据 + 历史曲线）
2. 动态 import 有额外开销
3. 后端 4 次独立 InfluxDB 查询
4. 无前端缓存

## 2. 优化方案

### 2.1 合并 API 请求
把历史曲线数据合并到 `/api/scenarios/{scenario}/popup` 接口里，一个请求拿所有数据。

**优化前**：2 个 HTTP 请求
**优化后**：1 个 HTTP 请求

### 2.2 去掉动态 import
直接导入 API 函数，去掉 `import('../api/client').then(...)` 这种动态写法。

### 2.3 前端缓存优化
react-query 设置 `staleTime: 5 分钟`，相同场景不用重复查询。

### 2.4 分阶段加载
先显示基本信息（成绩 + 基准 + 感悟），历史曲线后加载，感知速度更快。

### 2.5 后端合并查询
把 4 次 InfluxDB 查询合并成 2 次：
- 第 1 次：当天成绩 + 历史曲线（都是 aim_scenario measurement）
- 第 2 次：基准数据 + 历史感悟（不同 measurement，合并不了）

## 3. 预期效果

| 优化项 | 优化前 | 优化后 | 提升 |
| --- | --- | --- | --- |
| HTTP 请求数 | 2 个 | 1 个 | -50% |
| InfluxDB 查询数 | 4 次 | 2 次 | -50% |
| 感知加载时间 | 2-3 秒 | 0.5-1 秒 | -60% |
| 第二次打开同场景 | 重新加载 | 缓存，秒开 | 10x |

## 4. 实施步骤

1. 后端：popup 接口加上历史曲线数据
2. 后端：合并 aim_scenario 的 2 次查询
3. 前端：去掉动态 import，直接导入
4. 前端：react-query 设置 staleTime
5. 前端：分阶段加载，先显示基本信息
6. 四重验证
