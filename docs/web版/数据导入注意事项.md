# 数据导入注意事项

本文档记录所有数据导入相关的注意事项，每次导入新数据前必须先读一遍本文档。

---

## 一、Tag 规则

### 1.1 必须带 list tag

**规则：** 所有 `aim_scenario` measurement 的数据，必须带 `list=viscose-s2-easier` tag。

**原因：**
- Grafana 看板查询时过滤了 `list == "viscose-s2-easier"`
- Web 看板后端查询也过滤了 `list == "viscose-s2-easier"`
- 不带这个 tag 的数据会被过滤掉，查不到

**检查方法：**
导入后查一下：
```flux
from(bucket: "aim")
  |> range(start: -1d)
  |> filter(fn: (r) => r._measurement == "aim_scenario")
  |> keep(columns: ["list", "scenario"])
  |> limit(n: 10)
```
确认 `list` 字段都是 `viscose-s2-easier`。

---

### 1.2 场景名 tag 的转义

**规则：** 场景名作为 tag 值时，如果有空格或特殊字符，必须正确转义。

**常见坑：**
- 空格转义后带反斜杠，导致查询匹配不到
- 逗号、引号等特殊字符没转义，导致 Line Protocol 格式错误

**检查方法：**
导入后用场景名查一下，能不能查到数据：
```flux
from(bucket: "aim")
  |> range(start: -1d)
  |> filter(fn: (r) => r._measurement == "aim_scenario" and r.scenario == "1w2ts reload smallflicks larger")
  |> keep(columns: ["_value", "_field", "scenario"])
  |> limit(n: 5)
```

## 二、时间规则

### 2.1 时区注意事项

**规则：**
- InfluxDB 里存的时间都是 **UTC 时间**
- 用户打游戏的时间是 **北京时间（UTC+8）**
- 北京时间晚上 8 点 = UTC 当天中午 12 点

**常见坑：**
- 按北京时间算时间范围，直接转成时间戳，没减 8 小时，导致时间范围不对
- Python 进程时区是 UTC，`datetime.timestamp()` 算出来的时间戳比预期早 8 小时

**正确做法：**
```python
# 北京时间的日期，转成 UTC 时间戳
beijing_offset = 8 * 3600  # 8 小时的秒数
first_date = datetime.strptime('2026-09-18', '%Y-%m-%d')
start_ts = int(first_date.timestamp()) - beijing_offset
```

---

### 2.2 Flux 时间格式

**规则：** Flux 查询里的时间范围，必须用 RFC3339 格式的时间字符串，不要用 `int(v: xxx) * 1000000000` 的写法。

**错误写法：**
```flux
|> range(start: int(v: 1789632000) * 1000000000, stop: int(v: 1789718399) * 1000000000)
```
（InfluxDB 识别不了，查不到数据）

**正确写法：**
```flux
|> range(start: 2026-09-17T16:00:00Z, stop: 2026-09-18T16:00:00Z)
```

**转换方法：**
```python
from datetime import datetime

# 时间戳转 RFC3339 时间字符串（UTC）
start_str = datetime.utcfromtimestamp(start_ts).strftime('%Y-%m-%dT%H:%M:%SZ')
end_str = datetime.utcfromtimestamp(end_ts).strftime('%Y-%m-%dT%H:%M:%SZ')
```

## 三、CSV 解析规则

### 3.1 必须用标准 csv 模块

**规则：** 解析 CSV 文件时，必须用 Python 标准的 `csv` 模块，不能直接用 `split(",")`。

**原因：**
- 有些场景名里带逗号，直接 `split(",")` 会把场景名拆成两部分
- 有些字段里带引号，直接 `split(",")` 会解析错误

**正确写法：**
```python
import csv

with open('data.csv', 'r', encoding='utf-8') as f:
    reader = csv.DictReader(f)
    for row in reader:
        # row 是字典，key 是列名，value 是值
        scenario = row['scenario']
        score = row['score']
```

## 四、数据导入步骤

### 4.1 Kovaak's 数据导入

**步骤：**
1. 从 Kovaak's 的 Playlist 导出成绩数据
2. 转成标准 CSV 格式
3. 用导入脚本写入 InfluxDB
4. 导入后验证数据

**验证清单：**
- [ ] 数据量对不对（多少轮、多少个场景）
- [ ] 每个场景的分数对不对
- [ ] 时间是不是正确
- [ ] 有没有带 `list=viscose-s2-easier` tag
- [ ] Grafana 看板能不能看到
- [ ] Web 看板能不能看到

---

### 4.2 Aim Lab 数据导入

**步骤：**
1. 从 Aim Lab 导出成绩数据
2. 转成标准 CSV 格式
3. 写入 InfluxDB 的 `aimlab_task` measurement
4. 导入后验证数据

**注意事项：**
- Aim Lab 数据不需要带 `list` tag
- 字段名要和现有的保持一致（`score`、`accuracy`）
- 时间戳要正确

## 五、常见错误及排查

### 5.1 导入后查不到数据

**排查步骤：**
1. 先直接在 InfluxDB 里查，看数据有没有写进去
2. 检查 `list` tag 对不对
3. 检查场景名有没有转义错误
4. 检查时间范围对不对

---

### 5.2 数据错位

**排查步骤：**
1. 检查 CSV 是不是用标准 `csv` 模块解析的
2. 检查场景名里有没有逗号
3. 检查 Line Protocol 格式对不对

---

### 5.3 时间不对

**排查步骤：**
1. 检查时区是不是算对了（北京时间 UTC+8）
2. 检查 Flux 查询的时间格式对不对
3. 检查数据写入的时间戳对不对

---

## 六、导入后必须做的验证

每次导入新数据后，必须做以下验证：

1. **InfluxDB 层验证：** 直接查 InfluxDB，确认数据写进去了
2. **API 层验证：** 调用后端接口，确认能查到数据
3. **Web 前端验证：** 打开 Web 看板，确认数据显示正确
4. **Grafana 验证：** 打开 Grafana 看板，确认数据显示正确
