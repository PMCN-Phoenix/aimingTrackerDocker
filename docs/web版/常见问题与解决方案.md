# 常见问题与解决方案

本文档记录开发和使用过程中遇到的所有问题，以及对应的解决方案。遇到问题优先查看本文档。

---

## 一、数据显示问题

### 1.1 基准总览看板档位显示为空

**问题现象：**
基准总览看板里，档位分布显示全是 None，每个场景的 rank 字段是空的。

**问题原因：**
InfluxDB 里 `aim_bench_row` measurement 的 `rank` 字段是空的，完整的 rank 数据存储在 `rowJson` 字段里（是一个完整的 JSON 字符串）。后端查询时只查了独立的 `rank` 字段，没查 `rowJson` 里的完整数据。

**解决方案：**
修改后端 `get_all_bench_scenarios` 函数，从 `rowJson` 字段解析完整的 JSON 数据，包括：
- `rank` / `subRank`：档位名称（字符串）
- `cat` / `sub`：大类和子类
- `score` / `acc`：最佳分数和命中率
- `targets`：各档位的分数线数组
- `achIdx`：当前档位索引

---

### 1.2 Day1/Day2 数据显示"未开始"

**问题现象：**
今天清单看板里，所有场景都显示"未开始"，已打轮数都是 0。

**问题原因：**
两个问题叠加：
1. **时间范围不对**：`start_ts` 和 `end_ts` 是按 UTC 时间算的，但是用户是在北京时间（UTC+8）晚上打的游戏，实际数据的 UTC 时间比预期晚了一天。
2. **Flux 时间格式错误**：后端用 `int(v: xxx) * 1000000000` 的写法传时间戳，InfluxDB 识别不了，查不到任何数据。

**解决方案：**
1. **自动计算时间范围**：根据 `exec_dates` 字段（格式：`2026-09-19,2026-09-20`）自动计算时间范围，不用手动设 `start_ts`/`end_ts`。
2. **时区偏移**：Python 进程时区是 UTC，北京时间是 UTC+8，所以要手动减去 8 小时（28800 秒）。
3. **时间格式**：把时间戳转成 RFC3339 格式的时间字符串（如 `2026-09-18T00:00:00Z`），不要用 `int(v: xxx) * 1000000000` 的写法。

---

### 1.3 档位颜色显示不对

**问题现象：**
基准总览看板里的 9 个档位格子都是灰色的，看不出当前在哪个档位。

**问题原因：**
1. `currentRank` 传进来的是字符串（如 "Hare"、"Penguin"），但是代码里把它当成数字来比较，导致所有比较结果都是 false，所有格子都是灰色。
2. 子类平均档位计算也有同样的问题，把字符串当数字算，结果是 NaN。

**解决方案：**
1. 定义档位顺序数组：`['Unranked', 'Lemming', 'Ermine', 'Hare', 'Penguin', 'Puffin', 'Fox', 'Otter', 'Lynx']`
2. 写一个函数把 rank 字符串转成对应的数字索引
3. 按索引来判断颜色：
   - 绿色 = 已经通过的档位
   - 黄色（加粗）= 当前所在档位
   - 灰色 = 还没达到的档位

## 二、数据导入问题

### 2.1 导入数据必须带 list tag

**问题现象：**
导入了数据，但是 Grafana 看板和 Web 看板都查不到。

**问题原因：**
查询的时候都过滤了 `list == "viscose-s2-easier"` tag，如果导入的时候没带这个 tag，就会被过滤掉。

**解决方案：**
导入所有练枪数据时，必须带 `list=viscose-s2-easier` tag。

---

### 2.2 CSV 解析必须用标准 csv 模块

**问题现象：**
导入 CSV 数据时，逗号分隔错了，导致数据错位。

**问题原因：**
有些场景名里带逗号，如果直接用 `split(",")` 分割，就会把场景名拆成两部分，导致数据错位。

**解决方案：**
必须用 Python 标准的 `csv` 模块来解析 CSV 文件，不能直接用 `split(",")`。

---

### 2.3 URL 编码场景名不要重复编码

**问题现象：**
请求场景详情接口时，404 或者查不到数据。

**问题原因：**
场景名里有空格和特殊字符，编码一次之后，前端又编码了一次，导致后端拿到的场景名不对。

**解决方案：**
场景名只编码一次（`quote()` 一次就够），不要重复编码。

---

## 三、前端显示问题

### 3.1 感悟日期显示不对

**问题现象：**
历史感悟里的日期显示不对，或者显示成 Invalid Date。

**问题原因：**
后端返回的日期字段是 `date`（ISO 格式字符串），但是前端代码里用的是 `item.time * 1000`（时间戳格式），字段名不对，格式也不对。

**解决方案：**
把前端 `ReflectionList` 组件里的 `item.time * 1000` 改成 `new Date(item.date).toLocaleDateString()`。

---

### 3.2 Tailwind CSS v4 PostCSS 插件错误

**问题现象：**
启动前端开发服务器时报错，PostCSS 插件找不到。

**问题原因：**
Tailwind CSS v4 的 PostCSS 插件变了，不能直接用 `tailwindcss` 包，要用 `@tailwindcss/postcss` 包。

**解决方案：**
安装 `@tailwindcss/postcss` 包，然后在 `postcss.config.js` 里用这个包。

## 四、其他问题

### 4.1 git 不在 PATH 里

**问题现象：**
运行 git 命令时提示"不是内部或外部命令"。

**问题原因：**
Git 没有加到系统 PATH 环境变量里。

**解决方案：**
用完整路径运行 git：`D:\6_code\1_Git\Git\cmd\git.exe`

---

### 4.2 popup 接口加载慢

**问题现象：**
点击场景名打开弹窗时，加载很慢，要等好几秒。

**问题原因：**
之前弹窗要发 4 个 HTTP 请求：当天成绩、基准数据、历史感悟、历史曲线，每个请求都有开销，加起来就慢了。

**解决方案：**
合并成一个接口 `/api/scenarios/{scenario}/popup`，一次返回所有数据，减少 HTTP 请求次数。同时加 5 分钟缓存，第二次打开秒开。

---

## 五、导入数据检查清单

每次导入新数据后，按这个清单检查：

- [ ] 数据有没有带 `list=viscose-s2-easier` tag
- [ ] CSV 是不是用标准 csv 模块解析的
- [ ] 场景名有没有被错误拆分
- [ ] 时间戳是不是正确（注意时区）
- [ ] 导入后能不能在 InfluxDB 里查到
- [ ] 导入后能不能在 Web 看板里显示
- [ ] 导入后能不能在 Grafana 看板里显示
