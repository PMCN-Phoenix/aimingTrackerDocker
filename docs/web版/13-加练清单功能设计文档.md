# 加练清单功能设计文档

## 1. 功能概述

在每日练枪界面增加"加练内容"区域，用户打完主清单后，如果还想对薄弱点进行额外练习，可以创建加练清单来训练。

### 1.1 核心特点

- 每天可以有**多个**加练清单，每个有自定义名称
- 加练清单和主清单格式一致（场景列表 + 轮数 + 角色 + 目标线）
- 加练数据**独立记录**，不影响主清单完成度
- 每个加练清单生成独立的 Kovaak's playlist.json
- 成绩自动按**创建时间点**分配：创建前算主清单，创建后算加练

---

## 2. 核心概念

### 2.1 主清单 vs 加练清单

| 维度 | 主清单 | 加练清单 |
| --- | --- | --- |
| 数量 | 每天 1 个 | 每天 N 个 |
| 命名 | Day1, Day2, ... | Day4-extra-1, Day4-extra-2, ... |
| 显示名称 | "Day4 攻Arm" | 用户自定义（"Popcorn 专项加练"） |
| 创建流程 | 完整流程（文档→导入→关联） | 完整流程（和主清单一致） |
| 数据标记 | type=main | type=extra |
| 父级关联 | 无 | parent_daylist=Day4 |
| Kovaak's playlist | 有 | 有（独立文件） |

### 2.2 加练清单的内部 ID 规则

- 内部 ID：`{daylist}-extra-{序号}`，例如 `Day4-extra-1`、`Day4-extra-2`
- 显示名称：用户自定义，例如 "Popcorn 专项加练"、"Arm 巩固加练"
- 序号从 1 开始，按创建顺序递增

## 3. 数据结构设计

### 3.1 InfluxDB measurement: aim_daylist_meta

新增字段：

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| daylist | string (tag) | 清单 ID | `Day4-extra-1` |
| parent_daylist | string | 父级主清单 ID | `Day4` |
| type | string | 清单类型 | `extra`（主清单为 `main`） |
| name | string | 显示名称 | `Popcorn 专项加练` |
| exec_dates | string | 执行日期 | `2026-10-02` |
| created_at | integer | 创建时间戳（用于成绩分配） | `1790900000` |
| items | integer | 场景数量 | `3` |
| rounds_total | integer | 总轮数 | `12` |
| start_ts | integer | 开始时间戳 | `1790870400` |
| end_ts | integer | 结束时间戳 | `1790956799` |
| label | string | 标签 | `Day4 加练` |

### 3.2 InfluxDB measurement: aim_daylist

和主清单完全一致：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| daylist | string (tag) | 清单 ID（`Day4-extra-1`） |
| scenario | string (tag) | 场景名 |
| role | string | 角色（热身/主攻/巩固/卡口） |
| rounds | integer | 要求轮数 |
| order | integer | 顺序 |
| target_score | float | 目标分数（可选） |
| target_rank | string | 目标档位（可选） |

### 3.3 InfluxDB measurement: aim_scenario

新增 tag：

| tag | 说明 | 示例 |
| --- | --- | --- |
| type | 数据类型 | `main`（主清单）/ `extra`（加练） |
| daylist | 所属清单 | `Day4` / `Day4-extra-1` |

**成绩分配逻辑**：
- 导入当天成绩时，按时间戳分配
- 时间戳 < 加练清单 created_at → 算主清单（type=main, daylist=Day4）
- 时间戳 >= 加练清单 created_at → 算该加练清单（type=extra, daylist=Day4-extra-1）
- 主清单的完成轮数 = 当天所有轮数（不管创建时间点）
- 加练清单的完成轮数 = 创建时间点之后的轮数

### 4.2 加练清单卡片

每个加练清单是一个可折叠的卡片：

- **标题栏**：图标 + 名称 + 完成进度 + 操作菜单（⋮）
- **元信息**：创建时间、总轮数、完成状态
- **场景列表**：和主清单一样的场景行（可点击查看详情）
- **折叠/展开**：点击标题栏可以折叠/展开场景列表

### 4.3 操作菜单（⋮）

每个加练清单的操作菜单包含：

- 编辑清单（修改场景、轮数、名称）
- 导出 playlist.json（重新生成 Kovaak's 清单）
- 查看详情（完整的成绩和感悟）
- 删除清单（确认后删除）

### 4.4 新增加练清单按钮

- 位置：加练清单区域右上角
- 点击后跳转到加练清单创建页面（或弹出创建向导）
- 创建流程和主清单一致

## 5. 交互流程

### 5.1 创建加练清单流程

```
用户点击 [+ 新增加练]
    ↓
进入加练清单创建页面
    ↓
1. 填写基本信息
   - 名称（如 "Popcorn 专项加练"）
   - 关联日期（默认当天）
    ↓
2. 选择场景和轮数
   - 从场景库选择
   - 设置每个场景的轮数、角色、目标线
   - 调整顺序
    ↓
3. 预览和确认
   - 显示清单摘要
   - 确认创建
    ↓
4. 系统执行
   - 创建 markdown 文档
   - 生成 playlist.json
   - 导入 InfluxDB（元数据 + 清单项）
   - 复制 playlist.json 到 Kovaak's Playlists 目录
   - 记录 created_at 时间戳
    ↓
创建完成，返回当日页面
    ↓
新的加练清单显示在加练区域
```

### 5.2 打加练清单流程

```
用户在 Kovaak's 里选择加练清单 playlist
    ↓
开始打加练
    ↓
打完后，用户点击 [刷新] 或 [导入数据]
    ↓
系统读取当天所有 stats 文件
    ↓
按创建时间点分配：
   - created_at 之前的轮数 → 主清单
   - created_at 之后的轮数 → 加练清单
    ↓
更新主清单和加练清单的完成状态
    ↓
页面刷新，显示最新进度
```

### 5.3 查看加练详情流程

```
用户点击加练清单中的场景名
    ↓
弹出场景详情弹窗
    ↓
显示：
   - 当天成绩（主清单 + 加练，按时间排序）
   - 历史曲线（所有数据，不区分 main/extra）
   - 感悟记录
   - 目标对比
    ↓
用户可以切换查看：全部 / 仅主清单 / 仅加练
```

## 6. 成绩导入逻辑

### 6.1 核心规则

**主清单完成轮数** = 当天该场景的**所有**轮数（不管创建时间点）

**加练清单完成轮数** = 该加练清单 created_at 时间点**之后**的轮数

### 6.2 多份加练清单的分配

如果当天有多个加练清单，按 created_at 时间顺序分配：

```
时间轴：
  ├───── Day4 主清单（所有轮数都算）
  │
  ├── 18:00 开始打主清单
  ├── 20:30 创建加练1（Popcorn 专项）
  ├── 20:30-21:00 打加练1
  ├── 21:15 创建加练2（Arm 巩固）
  ├── 21:15-22:00 打加练2
  │
  └───── 轮数分配：
        18:00-20:30 的 Popcorn 轮数 → 主清单 + 加练1？不，只算主清单
        20:30-21:15 的 Popcorn 轮数 → 主清单 + 加练1
        21:15 之后的 SmoothBot 轮数 → 主清单 + 加练2
```

**注意**：
- 主清单的轮数是**累加**的，所有时间点的轮数都算主清单
- 加练清单的轮数是**从自己的 created_at 开始**算
- 不同加练清单之间按 created_at 区分，一个轮数只属于一个加练清单（或不属于任何加练清单，只算主清单）

### 6.3 场景匹配

- 加练清单里的场景和主清单里的场景可能相同（比如主清单有 Popcorn，加练1也有 Popcorn）
- 成绩按场景名匹配，同一个场景的所有轮数都算主清单
- 加练清单只统计 created_at 之后的轮数

## 7. Kovaak's 集成

### 7.1 playlist.json 生成

每个加练清单生成独立的 playlist.json：

- 文件名：`Viscose Day4 - 加练-Popcorn专项.json`（或 `Viscose Day4-extra-1.json`）
- 位置：Kovaak's Playlists 目录
- 格式：和主清单 playlist.json 完全一致

### 7.2 Playlists 目录文件管理

为了避免 Playlists 目录文件过多：

- 主清单：`Viscose Day1 - xxx.json`、`Viscose Day2 - xxx.json`...
- 加练清单：`Viscose Day4-extra-1 - Popcorn专项.json`、`Viscose Day4-extra-2 - Arm巩固.json`...
- 可以定期清理旧的加练清单 playlist 文件（但保留数据和文档）

## 8. API 设计

### 8.1 获取某日所有清单（主 + 加练）

```
GET /api/daylists?date=2026-10-02
```

返回：
```json
{
  "data": {
    "main": { ... Day4 主清单数据 ... },
    "extras": [
      { ... 加练1数据 ... },
      { ... 加练2数据 ... }
    ]
  }
}
```

### 8.2 获取单个加练清单详情

```
GET /api/daylists/Day4-extra-1/progress
```

返回格式和主清单完全一致。

### 8.3 创建加练清单

```
POST /api/daylists/extras
```

请求体：
```json
{
  "parent_daylist": "Day4",
  "name": "Popcorn 专项加练",
  "exec_dates": "2026-10-02",
  "items": [
    {
      "scenario": "Popcorn MV Easier",
      "role": "主攻",
      "rounds": 4,
      "order": 1,
      "target_score": 200
    }
  ]
}
```

### 8.4 更新加练清单

```
PUT /api/daylists/Day4-extra-1
```

### 8.5 删除加练清单

```
DELETE /api/daylists/Day4-extra-1
```

### 8.6 导出加练清单 playlist

```
POST /api/daylists/Day4-extra-1/export-playlist
```

## 11. 注意事项

1. **主清单完成度不受加练影响**：主清单的轮数是当天所有轮数，加练只是额外标记
2. **created_at 是关键**：加练清单的创建时间戳决定了成绩分配，必须准确记录
3. **加练清单可以随时创建**：即使主清单还没打完，也可以创建加练清单
4. **加练数据在历史曲线里全部显示**：场景详情和历史曲线不区分 main/extra，全部显示
5. **删除加练清单不删除成绩数据**：删除加练清单只是删除清单元数据和项，成绩数据仍然保留（只是不再标记为该加练）
6. **加练清单的目标线可选**：如果不设目标线，只显示完成轮数，不显示达标状态
