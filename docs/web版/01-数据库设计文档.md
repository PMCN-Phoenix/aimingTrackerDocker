# 01-数据库设计文档

## 1. 概述

本项目继续使用现有 InfluxDB 作为数据存储，本文档定义所有 measurement 的结构、tag、field 和关键查询模式，作为后端 API 设计的基础。

**InfluxDB 连接信息**：
- 地址：`http://127.0.0.1:8087`
- Org：`aim-org`
- Bucket：`aim`
- Token：`aim-super-secret-token-2026`

---

## 2. Measurement 总览

| Measurement | 用途 | 数据粒度 |
| --- | --- | --- |
| `aim_scenario` | 场景成绩（每次尝试的得分/命中率） | 每次尝试一行 |
| `aim_reflection` | 每日感悟 | 每个场景每天一条 |
| `aim_daylist` | 每日清单行（每个场景的配置） | 每个场景一行 |
| `aim_daylist_meta` | 每日清单元数据 | 每个清单一行 |
| `aim_bench_row` | 基准行数据（档位、达标线） | 每个场景一行 |
| `aim_bench_meta` | 基准元数据（子类统计） | 每个子类一行 |
| `aim_kill` | Kill 数据（备用） | 每次击杀一行 |
| `aim_log` | 日志数据（备用） | 每次操作一行 |
| `aim_note` | 笔记数据（备用） | 每条笔记一行 |
| `aimlab_task` | Aim Lab 任务数据（备用） | 每个任务一行 |

---

## 3. 核心 Measurement 详细设计

### 3.1 aim_scenario（场景成绩）

**用途**：存储每次场景尝试的得分和命中率，是看板的核心数据源。

**Tags**：

| Tag | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `scenario` | string | 场景名 | `1w2ts reload smallflicks larger` |
| `list` | string | 清单名 | `viscose-s2-easier` |
| `session_id` | string | 会话 ID | `s1789555415000` |
| `attempt_no` | string | 第几次尝试 | `1` |
| `source` | string | 数据来源 | `stats` |

**Fields**：

| Field | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `score` | float | 得分 | `100` |
| `accuracy` | float | 命中率（百分比） | `96.2` |

**时间戳**：
- 格式：RFC3339 UTC
- 含义：本次尝试的结束时间

**关键查询模式**：

```flux
# 1. 查某个场景在某段时间内的最佳成绩
from(bucket: "aim")
  |> range(start: _cs, stop: _ce)
  |> filter(fn: (r) => r._measurement == "aim_scenario" and r.scenario == "..." and r.list == "viscose-s2-easier")
  |> filter(fn: (r) => r._field == "score" or r._field == "accuracy")
  |> keep(columns: ["_time", "_value", "_field", "scenario"])

# 2. 查某个清单某段时间内打了多少轮
from(bucket: "aim")
  |> range(start: _cs, stop: _ce)
  |> filter(fn: (r) => r._measurement == "aim_scenario" and r.list == "viscose-s2-easier")
  |> filter(fn: (r) => r._field == "score")
  |> group(columns: ["scenario"])
  |> count()

# 3. 查某个场景的历史成绩趋势
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_scenario" and r.scenario == "..." and r.list == "viscose-s2-easier")
  |> filter(fn: (r) => r._field == "score")
  |> keep(columns: ["_time", "_value", "scenario"])
```

### 3.2 aim_reflection（每日感悟）

**用途**：存储每个场景每天的感悟，用于感悟弹窗展示。

**Tags**：

| Tag | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `scenario` | string | 场景名 | `Popcorn MV Easier` |
| `daylist` | string | 所属清单 | `Day1` |

**Fields**：

| Field | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `note` | string | 感悟文本 | `要顺着轨迹，找到重合同步的时候确认点击...` |

**时间戳**：
- 格式：RFC3339 UTC
- 含义：感悟对应的日期（当天 0 点）

**关键查询模式**：

```flux
# 1. 查某个场景的所有历史感悟
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_reflection" and r.scenario == "...")
  |> keep(columns: ["_time", "_value", "scenario"])

# 2. 查某天所有场景的感悟
from(bucket: "aim")
  |> range(start: _cs, stop: _ce)
  |> filter(fn: (r) => r._measurement == "aim_reflection")
  |> keep(columns: ["_time", "_value", "scenario"])
```

**注意事项**：
- scenario tag 值不能带反斜杠（之前踩过坑）
- 同一天同一个场景只能有一条感悟（重复写入会覆盖）

---

### 3.3 aim_daylist（每日清单行）

**用途**：存储每日清单的每一行配置，包括场景名、角色、轮数等。

**Tags**：

| Tag | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `daylist` | string | 清单名 | `Day1` |
| `scenario` | string | 场景名 | `CatClick Easier` |
| `role` | string | 角色 | `热身 / 卡口 / 主项 / 巩固 / 收尾` |

**Fields**：

| Field | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `order` | int | 顺序 | `7` |
| `rounds` | int | 要求轮数 | `9` |
| `rowJson` | string | 整行 JSON（含 target_score / target_acc 等） | `{"daylist": "Day1", "scenario": "CatClick Easier", ...}` |

**时间戳**：
- 格式：RFC3339 UTC
- 含义：清单创建日期

**关键查询模式**：

```flux
# 1. 查某个清单的所有行
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_daylist" and r.daylist == "Day1")
  |> filter(fn: (r) => r._field == "rowJson")
  |> keep(columns: ["_value", "scenario", "role"])
```

---

### 3.4 aim_daylist_meta（清单元数据）

**用途**：存储清单的元数据，包括执行日期、时间范围等，用于跨天统计。

**Tags**：

| Tag | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `daylist` | string | 清单名 | `Day1` |
| `label` | string | 清单标签 | `卡口双攻` |

**Fields**：

| Field | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `run_date` | string | 主要执行日期 | `2026-09-18` |
| `exec_dates` | string | 所有执行日期（JSON 数组） | `["2026-09-18"]` |
| `start_ts` | int | 开始时间戳（Unix 秒） | `1789920000` |
| `end_ts` | int | 结束时间戳（Unix 秒） | `1790006399` |
| `items` | int | 场景数 | `7` |
| `rounds_total` | int | 总轮数 | `33` |

**时间戳**：
- 格式：RFC3339 UTC
- 含义：清单创建日期

**关键查询模式**：

```flux
# 1. 查某个清单的元数据
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_daylist_meta" and r.daylist == "Day1")
  |> keep(columns: ["_value", "_field", "daylist"])

# 2. 查所有清单列表
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_daylist_meta")
  |> filter(fn: (r) => r._field == "run_date")
  |> keep(columns: ["_value", "daylist", "label"])
```

### 3.5 aim_bench_row（基准行数据）

**用途**：存储每个场景的基准数据，包括档位、达标线、差距百分比等。

**Tags**：

| Tag | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `scenario` | string | 场景名 | `Pasu Voltaic Reload Easier` |
| `list` | string | 清单名 | `viscose-s2-easier` |
| `cat` | string | 大类 | `CLICK TIMING` |
| `sub` | string | 子类 | `Reading` |
| `rank` | string | 当前档位 | `Hare` |
| `subRank` | string | 子类档位 | `Ermine` |

**Fields**：

| Field | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `nextLine` | float | 下一档线 | `52` |
| `pct` | float | 当前得分百分比 | `33.3` |
| `gapPct` | float | 差距百分比 | `7.7` |
| `achIdx` | int | 达标索引 | `2` |

**时间戳**：
- 格式：RFC3339 UTC
- 含义：基准更新时间

**关键查询模式**：

```flux
# 1. 查某个场景的基准数据
from(bucket: "aim")
  |> range(start: -30d)
  |> filter(fn: (r) => r._measurement == "aim_bench_row" and r.scenario == "..." and r.list == "viscose-s2-easier")
  |> keep(columns: ["_value", "_field", "scenario"])
```

**时间戳**：
- 格式：RFC3339 UTC
- 含义：基准更新时间

## 4. 和现有 Python 脚本的映射

| 脚本 | 操作的 Measurement |

| `bench_rows.py` | 写入 `aim_bench_row` 和 `aim_bench_meta` |

| `aimlab_import.py` | 写入 `aim_scenario` 和 `aimlab_task` |
| `reflection_table.py` | 写入 `aim_reflection` |
| `build_dashboard.py` | 读取所有 measurement，生成 Grafana 看板 |

---

## 5. 设计原则

1. **不修改现有数据结构**：继续用现有的 InfluxDB measurement 和 tag/field，保证现有脚本和 Grafana 看板不受影响。
2. **后端只做读取**：第一版后端 API 只做查询，写入操作继续用现有 Python 脚本完成。
3. **统一时间范围**：所有跨天统计都用 `aim_daylist_meta` 里的 `start_ts` / `end_ts` 来确定时间范围。
4. **场景名作为主键**：所有 measurement 都用 `scenario` tag 关联，保证跨表查询一致。
