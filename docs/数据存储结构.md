### 数据质量问题（上传前建议处理）

1. **同一批数据「双 list」重复（本次新发现，119 条）**：
   - **10-14**：55 条 `list=strafe-aiming-day9` + 55 条 `list=viscose-s2-easier`，对应同样的 55 个 stats 文件
   - **10-08**：69 条 `list=viscose-s2-easier` + 64 条 **无 list tag**，对应同样的 69 个文件
   - **成因**：`import_all_stats.py` 里 `LIST_NAME = "viscose-s2-easier"` 是**硬编码常量**。批量导入在不同时期跑过两遍，后一遍把「本该标 day9」的数据又用兜底 list 写了一次。InfluxDB 只在 `(measurement, tagset, timestamp)` 完全相同时才覆盖，**list 不同 = 两条独立 series**，于是并存。
   - **影响**：按 list 过滤的看板不受影响；**全量统计会多算 119 条**（1490 里有 1371 是真实记录）。
   - **待处理**：删除 10-14 的 55 条 `viscose-s2-easier` + 10-08 的 64 条无 list 记录。删除前需确认（属破坏性操作）。
2. **`list` tag 现有 3 个取值**：`viscose-s2-easier`（1316）、`strafe-aiming-day9`（110）、**空值**（64）。
   - LG56 热身（92 条）全标成 `viscose-s2-easier`——按约定有意为之，但语义上不对；正式分析前建议新建 `list=lg56-warmup` 或补 `source` tag。
   - 10-21 重打 Day9 清单（14 场景 55 轮）已按 `strafe-aiming-day9` 录入，与 10-14 同口径。
3. **伪 measurement**：`scenario=1w2ts reload smallflicks larger` —— 某次写入少了 measurement 前缀，整行被解析成 measurement 名（1 条，2026-09-17），应删除。
4. **三张成绩表并存**：`kovaak_score`（主用，1490 条）/ `aim_scenario`（1012）/ `kovaaks_score`（10）语义重叠，`vdim_score`（377）也可能部分重叠。合并前必须先确认去重口径。
5. **`aim_daylist_item` 空表**（只有 tag 骨架，无 field）、`????` 场景名 1 个（142 个 scenario tag 之一）。
6. **time 精度**：`aim_bench_row`、`aim_bench_meta` 只有 2026-10-19 一个时间点（快照式写入，非时序）。
