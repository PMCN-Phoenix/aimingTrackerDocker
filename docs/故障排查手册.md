## 一、看板数据显示问题

### 问题 1：D 看板（今日清单）显示的清单是旧版，不是最新写入的

**现象**：改了清单后，Grafana 显示的还是旧版场景列表，或者新旧版混在一起。

**原因**：InfluxDB 里同一个 daylist 有多个版本的 rowJson 数据（每次写入都追加，没有覆盖）。

**解决方案**：
1. 清理旧版数据，只保留最新版：
   ```python
   # 用 InfluxDB Delete API 删除旧时间范围的数据
   POST /api/v2/delete?org=aim-org&bucket=aim
   {
     "start": "2026-01-01T00:00:00Z",
     "stop": "2026-09-20T16:00:00Z",  # 改成新版 timestamp 之前的时间
     "predicate": '_measurement="aim_daylist" AND daylist="Day3"'
   }
   ```
2. 重新写入最新版清单

**正确流程（重写清单 = 先删后写）**：
1. **先删**：删除整个 daylist 的所有旧版数据（rowJson + meta）
   ```python
   delete_data("2026-01-01T00:00:00Z", "2027-01-01T00:00:00Z", 
               '_measurement="aim_daylist" AND daylist="Day3"')
   delete_data("2026-01-01T00:00:00Z", "2027-01-01T00:00:00Z", 
               '_measurement="aim_daylist_meta" AND daylist="Day3"')
   ```
2. **再写**：重新写入最新版清单

**为什么不能直接覆盖？** 因为每次写入的 timestamp 可能不同，InfluxDB 不会自动合并。先删后写最干净，不会留垃圾数据。

### 问题 1.5：一个清单跨了好几天才打完，run_date 怎么填？

**现象**：Day2 计划 9/19 打，但 9/19 只打了热身，9/20 才打完整个清单。

**解决方案**：
- `run_date` 填**实际完成日期**，不是计划日期
- 比如 Day2 实际 9/20 打完，run_date = "2026-09-20"
- 这样看板统计"已打轮数"时，查的是 9/20 当天的轮数，才对得上

**看板 URL 也要对应改**：`&var-rundate=2026-09-20`

---

### 问题 1.6：重复录入怎么办？

**现象**：同一个清单写了好几次，看板上每个场景显示两遍。

**解决方案**：
1. **写入前先删**：每次重写清单，必须先执行"先删后写"流程
2. **不要手动多次写入**：清单改了就改 markdown 文件，然后一次性写入
3. **如果已经重复了**：执行问题 1 的清理流程，然后重新写入一次

---

### 问题 2：看板上目标分 / 门槛都是 "—"

**现象**：D 看板 800/810 面板里，目标分、门槛列都是 "—"。

**原因**：写入 rowJson 时 `target_score` 和 `target_acc` 都是 `null`，没有填。

**解决方案**：
1. 重新写入 rowJson，补上 `target_score` 和 `target_acc` 字段
2. 注意：热身类场景可以不填 target_score，但最好填 target_acc（命中率门槛）

---

### 问题 3：看板上"已打轮数"比预期多很多

**现象**：某个场景要求打 2 轮，但显示"已打 14 轮"。

**原因**：当天除了清单要求的轮数，还打了其他额外的轮数（比如单场景练习）。Grafana 统计的是当天该场景的总轮数。

**这不是 bug**，是正常的——说明你当天多打了。如果想只看清单内的轮数，需要在导入时加 list tag 区分。

## 二、数据导入问题

### 问题 4：Kovaak's stats CSV 解析失败（score/hits/misses 都是 0）

**现象**：导入脚本跑了，但 InfluxDB 里 score 都是 0，或者根本没写入。

**原因**：Kovaak's 的 stats CSV 格式不是标准的"第一行 header + 第二行数据"，而是：
- 前 N 行是击杀明细（每行一个击杀）
- 然后空行
- 然后才是汇总信息（Score:, Hit Count:, Miss Count: 等）

**解决方案**：
1. 不要用 csv.reader 读第二行当数据
2. 逐行扫描，找 `Score:`、`Hit Count:`、`Miss Count:`、`Scenario:` 开头的行
3. 注意：这些行的格式是 `Score:,91.0`（冒号后面有个逗号），需要 `lstrip(",")`

**正确的解析代码**：
```python
def parse_csv(path):
    with open(path, "r", encoding="utf-8") as f:
        lines = f.readlines()
    summary = {}
    for line in lines:
        line = line.strip()
        if line.startswith("Score:"):
            val = line.split(":", 1)[1].strip().lstrip(",").strip()
            summary["score"] = float(val)
        elif line.startswith("Hit Count:"):
            val = line.split(":", 1)[1].strip().lstrip(",").strip()
            summary["hits"] = int(val)
        elif line.startswith("Miss Count:"):
            val = line.split(":", 1)[1].strip().lstrip(",").strip()
            summary["misses"] = int(val)
        elif line.startswith("Scenario:"):
            val = line.split(":", 1)[1].strip().lstrip(",").strip()
            summary["scenario"] = val
    return summary if "score" in summary else None
```

### 问题 5：数据导入后看板上看不到新数据

**现象**：导入了新数据，但 Grafana 看板上没显示。

**原因 1**：Grafana 时间范围不对。检查右上角时间选择器，确保覆盖了当天。
**原因 2**：数据的 run_date tag 和 var-rundate 参数不匹配。
**原因 3**：数据没有 list = "viscose-s2-easier" tag，Grafana 查询时过滤掉了。

**解决方案**：
1. 确认看板 URL 里有 `&var-rundate=2026-09-21`（改成实际日期）
2. 或者手动设置 Grafana 时间范围为今天
3. 导入数据时确保有正确的 tag

## 三、InfluxDB 操作问题

### 问题 6：删除数据时把想要的数据也删了

**现象**：执行 delete API 后，发现新版数据也没了。

**原因**：delete API 的 stop 参数是**半开区间** [start, stop)，如果你 stop 时间正好等于新版 timestamp，可能会因为精度问题删掉。

**解决方案**：
1. stop 时间要比新版 timestamp **晚 1 秒以上**，而不是正好等于
2. 或者直接删除整个 measurement 的某个 daylist，然后重新写入

---

### 问题 7：写入 rowJson 后看板显示乱序或重复

**现象**：看板上场景顺序不对，或者同一个场景出现多次。

**原因**：rowJson 里的 order 字段没写对，或者同一个 scenario 写了多次。

**解决方案**：
1. 确保每个场景的 order 字段唯一且连续（1, 2, 3, ...）
2. 如果同一个场景要分两段（比如校准段+追分段），用 order 区分，但 scenario tag 要加后缀或用不同 order 区分
3. 重新写入前先清理旧数据

## 四、Git 问题

### 问题 8：git push 显示 exit code 1，但实际推送成功了

**现象**：PowerShell 里 git push 返回 exit code 1，但 stdout 显示 "main -> main"。

**原因**：PowerShell 把 stderr 当成错误，git 的正常输出（如 remote: Powered by GITEE.COM）走 stderr。

**这不是真的错误**，推送实际成功了。

## 五、Kovaak's 相关问题

### 问题 9：Playlist 复制到 Kovaak's 后不显示

**现象**：把 playlist json 复制到 Kovaak's Playlists 目录，但游戏里找不到。

**原因**：
1. Kovaak's 正在运行，没刷新
2. playlist json 格式不对（字段名大小写错误）
3. playlistId 重复

**解决方案**：
1. 完全关闭 Kovaak's 再重新打开
2. 检查 json 格式：`playlistName`、`scenarioList`、`play_Count` 字段名要完全正确
3. 确保 playlistId 唯一

## 六、快速检查清单

出问题时按这个顺序查：

1. **数据写入了吗？** → 用 Flux 查询 InfluxDB，确认数据存在
2. **时间范围对吗？** → Grafana 右上角时间选择器，var-rundate 参数
3. **tag 对吗？** → list = "viscose-s2-easier"，daylist = "Day3"
4. **字段名对吗？** → score / accuracy / hits / misses，不是 Score / Accuracy
5. **rowJson 格式对吗？** → target_score / target_acc 字段有没有填
6. **有没有重复数据？** → 同一个 daylist 有没有多个版本叠加

## 七、常用查询命令

### 查某 daylist 有多少条 rowJson
```flux
from(bucket: "aim")
  |> range(start: -7d)
  |> filter(fn: (r) => r._measurement == "aim_daylist" and r.daylist == "Day3")
  |> group(columns: ["_field"])
  |> count()
```

### 查某天某场景的成绩
```flux
from(bucket: "aim")
  |> range(start: 2026-09-21T00:00:00+08:00, stop: 2026-09-21T23:59:59+08:00)
  |> filter(fn: (r) => r._measurement == "aim_scenario" and r._field == "score" and r.scenario == "cloverRawControl Viscose Easier 50cm")
  |> keep(columns: ["_time", "_value"])
  |> sort(columns: ["_time"])
```

### 删除某 daylist 的所有数据
```python
# POST /api/v2/delete?org=aim-org&bucket=aim
{
  "start": "2026-01-01T00:00:00Z",
  "stop": "2027-01-01T00:00:00Z",
  "predicate": '_measurement="aim_daylist" AND daylist="Day3"'
}
```
