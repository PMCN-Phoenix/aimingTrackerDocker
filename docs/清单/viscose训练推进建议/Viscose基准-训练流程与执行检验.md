## 一、这套东西是什么

**The Viscose Benches**（Viscose 基准）。作者一句话定位：

> "**一个伪装成 benchmark 的练习播放列表**（a practice playlist disguised as a benchmark）。"

设计初衷（视频原话）：

> "我的目标是**骗人们去玩那些适合练习的场景**，而不只是评估技能水平。技能目标是拍上去的激励，不是重点。重点是**发展扎实的基本功和好技术，能迁移到任何游戏**。"

### 和 Voltaic 的关键区别

| 维度 | Voltaic Benchmarks | Viscose Benches |
| --- | --- | --- |
| 设计目的 | 测试技能，画出最完整的画像 | 当**训练工具**用，发展可迁移基本功 |
| 分类逻辑 | 按"用哪种瞄准"，各类场景数**均等** | 按"**场景做什么用**"，场景数**不均等**分配 |
| 覆盖取向 | 广而全 | 窄而深（只留游戏内转化最有用的） |
| 子类别 | 有 target switching | **取消 target switching**，并入 Flick Tech |
| 拿 rank 条件 | energy 系统（3–4 个分数即可） | **每个子类别至少 1 分（≥14 分）** |
| 难度命名 | 暗示玩家水平 | 只指**场景本身的难度** |
| 档位衔接 | 跳变剧烈（master→grandmaster 断层） | **每档之间约 2 个 rank 重叠** |

作者自己的评价：这套东西"可能不如 Voltaic 一致，覆盖的瞄准领域也没那么广"，但它是按**对他个人瞄准发展最有用**的场景来组织的。

## 二、5 条必须先理解的核心机制

### 1. 分类按"场景做什么用"，不按"场景是什么"

这是整套体系的地基。作者原话：

> "不是根据**任务是什么**来分类，而是根据**任务做什么**来分组。"

四组主类别 + 它们的细分维度：

| 主类别 | 细分维度 | 子类别 |
| --- | --- | --- |
| **Control Tracking** | 按**肌群** | Arm / Wrist / Fingertip / Blending |
| **Reactive Tracking** | 按**技术** | Control / Speed / Reading |
| **Flick Tech** | 按**甩枪的哪一段** | Speed / Stability / Micro / Evasive（中高档为 Post-flick） |
| **Dynamic Clicking**（中高档叫 Click Timing） | 按**技术** | Reading / Precision / Linear（中高档为 Stability） |

**为什么这点重要**：低分不再是笼统的"要多练 tracking"。作者的例子——

> "Control Tracking 里 fingertip 子类别分数偏低，不只是告诉你'去练 tracking'。它非常具体地指向**小幅度精细控制的弱点**（指尖或手腕，取决于你的握法和灵敏度）。"

所以**子类别的相对低分 = 你的技术诊断书**。

### 2. 不要把它当播放列表一路打到底

作者明确**不推荐**把 benchmark 当 playlist 连打（"虽然你这么做我确定也有收益"）。理由：

> "benchmark 的价值在于，它让你**逐类别地给自己设定目标、推动自己提升**。"

### 3. 每个任务都是"优化的测试"（test of optimization）

这是整套方法里最核心的执行动作。作者的原话：

> "我对每一个任务的处理方式，都是一个**优化的测试**。**从技术的角度，我做错了什么，是这个场景在逼我改进的？**"

他给的自例：

> "我最近的一个例子是 pasu。我**没有正确地 lead（提前量/预瞄）我的射击**，而试图把分数往上推，逼我改进我的技术。"

**目的**：**防止自动驾驶（autopiloting）**，强制你主动分析自己的提升。

### 4. 难度 ≠ rank 所需技术，而且必须两档并行

这是最容易被误读的一点。视频里专门花时间澄清：

- 常见疑问："为什么 X 在 easier 里却被评为这么难？"
- 很多人反馈"fuchsia 比 wool 难多了"（fuchsia 是 medium，wool 是 hard）——**作者说：你们是对的，这是故意的**。
- **easier / medium / hard 代表的是场景的难度，不是达到某个 rank 所需的技术。** 会有作者本人认为是 advanced 的玩家，拿不到 medium 档的最高 rank。

设计意图：Voltaic 的问题是从 master 到 grandmaster，你不仅要把分数打更高，还要在明显更难的场景上打出来，跳变太剧烈，所以很多人误以为"master 之后 aim trainer 就没用了"。Viscose 的解法是**每档之间留约 2 个 rank 的重叠**。

由此推出一条核心训练原则：

> "我把 easier 的场景看作**技术的精炼**（refinement），harder 的场景看作对这套技术的**压力测试**（stress test）。你**真的应该同时练两者**。"

> "这里**强烈鼓励你持续练低于你最高可拿分档位的那一套 benchmark**。我现在离最高档也不远，但我依然从 medium 难度的场景里获得很大价值。"

### 5. rank 需要"每个子类别至少拿到一个分数"

- 舍弃了 Voltaic 现在的 energy 系统，**回到 Voltaic 的旧系统**：每个子类别至少 1 分才能获得 rank。
- 这里的门槛是**至少要 14 个分数**（Voltaic 只需 3–4 个）。
- 两个理由：
  1. 逼你玩更广范围的场景 → 自然变得更**全面（well rounded）**；
  2. 单项分数目标因此可以设得更低 → 更可达、更激励人。
- 作者原话："即使我想让 fuchsia 等同于 voltaic nova 的水平，fuchsia 的分数目标也可以做到**容易得多**，我个人觉得这更有激励性。"

### 2. 把场景导入 Kovaak's

**方式 A（表格自带 playcode）**——在 Kovaak's 的 playlist 输入框里直接贴：

| 档位 | Playcode |
| --- | --- |
| Easier | `KovaaKsGearingMehLowground` |

**方式 B（评论区更推荐的省事做法）**——上 **`evxl.app`**：
1. 网址栏输入 `evxl.app`
2. 搜到这份 benchmark 列表
3. 填你的 **Steam 个人资料链接** → 自动读出你的 Kovaak's 成绩
4. 网页上会生成一个 playlist → **开着 Kovaak's 点一下就能直接导入**

（评论里有人补充：场景本身在 Kovaak's 或 Aim Lab 里也能直接搜到名字。）

### 3. 硬性设置要求（表格明确声明，不满足则分数无效）

- ⚠️ **Fingertip 类场景：灵敏度慢于 50cm 的分数无效**
- ⚠️ **所有场景：最低 103 hfov**

### 4. 表格里的两个概念

- **threads**：每个场景旁的数字。**越接近该场景的达标线，拿到的 threads 越多**。它反映你成绩单的整体强度，**但不影响 rank**。总 threads 在表格顶部汇总。
- **每个 tab 的难度**：指这个 tab 里**场景**的难度，不是"什么样的人该打这个 tab"。作者特别说明——**Medium 档场景的 rank，能一直延伸到 Voltaic advanced 档专属的水平**。

### 5. 已知的坑（评论区反馈）

- 有用户反馈：**复制表格后输入成绩，`progress` 栏和段位栏不显示进度条**（评论区提出后未获解答）。推测是复制后条件格式/公式未随行生效——建议**直接在自己的 Google Sheets 里填写**，不要导出成 Excel 再填。
- 表格访问需梯子（有人因此做了网盘备份）。

## 四、详细训练流程

### 阶段 0 · 摸底（第一次，约 60–90 分钟）

**目的**：定位你的主档位 + 拿到初始弱点分布图。

1. 打开 **Easier** 档，36 个场景**每个打 1–3 次**。不要追分，只要有一个能填进表格的数字。
2. 把成绩填进表格。
3. 读两个结果：
   - **threads / rank 阶梯**：你现在大概落在哪一级（Lemming → Seal）
   - **子类别分布**：哪几个子类别**明显相对偏低**——特别看四个肌群类（Arm / Wrist / Fingertip / Blending）和技术类
4. 按官方建议判定主档位：
   - 能**舒适拿到 Mammoth** → 去试 **Medium**
   - 在 Medium 打到 **Lavender / Indigo** 附近 → 开始试 **Hard**

### 阶段 1 · 建立基线（第 1 周）

**目的**：把"能拿分"的场景铺满，凑够第一个 rank 所需的分。

1. **主档 + 上一档并行**（这是硬要求，见机制 4）：
   - 例：主练 Medium，那么 Easier 也必须每天打一部分
   - 原因：低档是"技术精炼"，高档是"技术压力测试"，两者互为校准
2. 优先把**每个子类别都打出至少 1 个分数**（拿 rank 的硬门槛，≥14 分）。
3. 这个阶段**不追高分**，目标是"全类别有数"。

### 阶段 2 · 主训练循环（日常，建议 40–60 分钟）

每次训练按这个顺序走：

```
① 热身 5-10 分钟
   └ 低档（= 技术精炼档）挑 2-3 个场景，每个 3-5 遍
     目标：手感 + 动作质量，不看分数

② 主课 25-35 分钟
   └ 主档：按"子类别"成组练（一次只攻 1 个子类别，3 个场景全打）
     例：今天攻 Control Tracking / Wrist → Leaptrack、Controlsphere rAim、VT Controlsphere
     目标：每个场景打到接近或超过该子类达标线

③ 压力 10-15 分钟
   └ 上一档（更难的档）挑 1-2 个场景，各 3 遍
     目标：暴露技术的极限问题，不求分

④ 归因 5 分钟（本方法最关键的一步）
   └ 对今天分数最低的那个场景，写下：
      "这个场景逼我改进的技术点是：______"
      "我具体做错了什么：______"
```

**④ 是不可跳过的**。跳过它就等于把 benchmark 退化成 playlist，方法的全部价值就在这里（机制 2 与 3）。

### 阶段 3 · 弱点补强（每周 1–2 次）

1. 从表格里找出**最弱的 1–2 个子类别**。
2. **找变体**（作者推荐的具体手法）：
   > "我喜欢的做法就是**搜索基础场景名去找变体**。比如输入 `clover raw control`，会跳出一大堆版本——slower、faster、larger、加 blink——每一个变化都在练不同的东西。"
3. 每条变体针对的点：

| 变体方向 | 练什么 |
| --- | --- |
| slower / 降速 | 动作质量、路径精度（把速度降下来才暴露出多余动作） |
| faster / 提速 | 反应与预判（来不及修正，逼你提前量） |
| larger / 加大目标 | 大范围位移的发力（手臂/手腕主导） |
| smaller / 缩小目标 | 精细控制（指尖主导）、微调 |
| 加 blink | 抗突然位移、重获取（reacquire） |

4. 也可以去看其他更窄聚焦的 benchmark、Vltag 的推荐场景列表、别人做的 playlist，来定向补弱。

## 五、执行检验

分三层：**过程检验**（有没有按方法练）、**结果检验**（分数有没有动）、**方法检验**（有没有退化成刷分）。

### A. 过程检验 —— 每次训练（5 分钟内完成）

| 检查项 | 合格标准 |
| --- | --- |
| 两档并行了吗 | 低档热身 + 主档主课 + 高档压力，三段都有 |
| 是"成组练子类别"还是"随机打" | 一次只攻 1 个子类别，组内 3 个场景都打 |
| 归因写了吗 | 有 ≥1 条具体的"这个场景逼我改进的技术点是…" |
| 有没有自动驾驶 | 如果一轮打完说不出任何技术问题 → 判定为自动驾驶，本轮无效 |

### B. 结果检验 —— 每 2 周一次（复测）

固定每 14 天做一次**全量复测**（主档 36 场景各 1 次），对比：

1. **rank 是否提升**（对照下表阶梯）
2. **threads 总数是否上升**（反映整体强度）
3. **最弱子类别是否收窄** —— 这是最关键的指标。看的是"最低子类别分数 / 该子类达标线"这个**比值**有没有上升，而不是绝对分。
4. **子类别之间的方差是否变小** —— 方差变小 = 你正在变得"全面"（这套体系的明确目标）

> ⚠️ 只有在**满足硬性设置**（fingertip ≥50cm、hfov ≥103）时这些数字才有效。

### C. 方法检验 —— 每月一次（防止跑偏）

- 回看上个月的练分记录：是否超过 60% 的时间都在打自己**已经能拿 rank 的简单场景**？
  → 是的话，说明你在**刷分舒适区**，需要往上一档加压力。
- 是否**只打自己擅长的类别**？
  → 是的话，违反"每个子类别都要有分数"的设计意图，立刻补最弱子类。
- 是否有连续 2 周**没写归因**？
  → 是的话，说明已经退化成 playlist 模式。

### D. Rank 阶梯（对照表）

**Easier 档（8 级）**
`Lemming → Hare → Ermine → Penguin → Fox → Mammoth → Orca → Seal`

**Medium 档（8 级）**
`Cinnabar → Vermillion → Saffron → Celadon → Cerulean → Lavender → Indigo → Fuchsia`

**Hard 档（6 级）**
`Wool → Linen → Velvet → Chiffon → Satin → Silk`

**档位切换判据（官方）**：
- 舒适拿到 **Mammoth** → 可试 Medium
- Medium 到 **Lavender / Indigo** → 可试 Hard
- 但**永远保留低档**（机制 4）

**表格怎么用**（玩家实测步骤，原话）：

### B. 社区共识：练这个对实战到底有没有用

这是评论区问得最多的问题（"瓦练这个有用吗"、"能练 CS2 吗"）。最高质量的两个回答：

> "练这个只是提升瞄准能力然后再兼容瓦。**想要提升的话需要长期练，短期无效**。如果瞄准能力有短板并且影响到瓦——比如准星很抖，或者移动中不能把准星保持在固定范围——练这个就比在游戏里有效。" —— 亡离诧（2 赞）

关于 CS2 / 短 TTK 游戏的争论：
- 一方（下等馬_Libe）："大部分都是动态项目，CS 专项还是看 kvk 自带的 1w6t 这类静态项目"
- 另一方（君寻寻寻寻，2 赞）："这套是很综合的，并不是说短 TTK 游戏就只练静态项目就够了。**练完对你自身的提升非常大，瞄准基本功和发力方式会很强**。就拿 CS 的路人王赵兴隆来说，他跑去玩 Apex 这种长 TTK 游戏后回来玩 CS 也进步了不少。"

**结论**：它训练的是**通用瞄准基本功**，不是某个游戏的专项。想立刻上分，不如直接练游戏；想解决"准星抖 / 移不动枪"这类底层问题，它比在游戏里硬练有效——**但要按长期投入算**。

### D. 练之前要有心理准备的痛点

   → 对应表格硬性要求：**fingertip 场景灵敏度须 ≥50cm**。低敏玩家要留意这类项目的有效性。

2. **缺少"快甩"类项目**
   > "顶多涵盖了当下流行的中低敏 FPS，**缺少像宽墙 2 目标和 pump flick 那样的练习快甩的项目**。" —— 中华田园保（5 赞）

3. **跟枪（tracking）是普遍难点**

4. **"打不完"的错觉**
   > 问："有几个项目十几分钟是咋回事？" → 答："那个按目标数算的，打完几个就结束，不会真打那么久的。"

### E. 尚未解决的开放问题

- **不同项目该不该换灵敏度**：有玩家问"不同的项目用什么样的灵敏度，还是都用平时用的"，无人回答。表格只规定了**下限**（fingertip ≥50cm、hfov ≥103），没规定具体值。→ 建议先固定用平时灵敏度，只确保满足下限。

## 七、和你现有练枪体系的衔接

你目前（`aim-tracker-docker`）跑的是 **12 场景 + 节拍（BPM）** 的日更体系，其中和 Viscose Benches 直接重叠/同源的场景不少：

| 你的现有场景 | Viscose Benches 对应 |
| --- | --- |
| Smoothbot Iron | Control Tracking / Arm —— Smoothbot Invincible 系 |
| Pasu Voltaic Iron | Dynamic Clicking / Precision —— Pasu 系 |
| Wide Wall 3 Targets TE / 1w2t TE Reload | Flick Tech / Speed —— 1w3ts 系 |
| Air Voltaic | Reactive Tracking / Reading —— Air 系 |
| B90T Voltaic | Dynamic Clicking / Reading —— B180 系 |
| Centering 90 | Control Tracking（血统上是 Voltaic 场景） |

**建议的衔接方式**（不必推倒现有体系）：

1. **现有 12 场景日更体系 = 你的"主课"**（节拍 + 命中率门槛，继续保持）。
2. **Viscose Benches = 你的"诊断 + 周期性复测层"**：
   - 每 2 周用 Viscose Medium 做一次全量复测 → 得到**子类别弱点分布**
   - 把弱点结论喂回日更体系：例如复测显示 **Wrist 子类别**偏低 → 在日更里加练 Wrist 类场景（Controlsphere rAim / Leaptrack）
3. **节拍与 Viscose 的关系**：Viscose 的 36 场景**没有节拍概念**，是纯分数体系。你现有的节拍目标（Pasu 40 / Tamspeed 100 / Wide Wall 100 / 1w2t 110）继续作为"动作节奏"的训练锚点；Viscose 负责"分数与技术诊断"。两者一个管**怎么动**，一个管**动得对不对**。
4. **可选**：把 Viscose 复测分数录进 InfluxDB（新 measurement，如 `viscose_bench`），在 Grafana 里做子类别雷达图/趋势，让"最弱子类别"的变化可视。要做的话我可以接着搭。
